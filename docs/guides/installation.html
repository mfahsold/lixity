Install Lixity and open a manuscript locally

Lixity analyzes Markdown manuscripts on your computer. It produces an interactive dashboard with sentence rhythm, vocabulary, readability and chapter-level style signals. No manuscript upload or account is required for core analysis.

Maintained by the Lixity project · Updated 3 October 2026

What do I need?

Use Python 3.10 or newer, Git, and uv. Python 3.12 is the documented default. Downloading the package and its dependencies requires an internet connection; core manuscript analysis runs offline afterward. Linux, macOS and Windows are supported. PDF research import has additional local prerequisites described in the OCR guide.

License: Lixity is source-available under LNCL-1.0. Free use is limited to projects with no commercial purpose. Books intended for sale, including self-publishing, require a separate written commercial license. Read the licensing examples.

Install a reproducible release

uv tool install --python 3.12 "git+https://github.com/mfahsold/lixity.git@v1.23.0"
lixity --version
lixity about

The tag selects a fixed release. If the command is not found, run uv tool update-shell, reopen the terminal and try again. Lixity is installed from GitHub; these instructions do not assume a PyPI package.

Included in v1.18.0 & v1.19.0: origin-URL metadata, browser PDF uploads, localized OCR diagnostics, Zotero integration and scoped search. Release v1.20.0 adds native project NDA encryption, multi-file batch ingestion with live progress, auto-fresh search index caching, section-bounded reading and decision-dossier review tracking. Release v1.22.0 adds cross-platform server lifecycle scripts, a decomposed native server package, and valid NDA PDF receipts. To follow development deliberately, replace the installation with:

uv tool install --force --python 3.12 "git+https://github.com/mfahsold/lixity.git@main"

main changes over time. Record the installed commit for reproducible automation and review the changelog. Installing or updating Lixity does not restart an already running server.

Create the first dashboard

Save this synthetic text as sample.md. Two short chapters are sufficient to exercise the workflow, but not to establish a reliable stylistic baseline.

## Chapter 1

The rain stopped. Mara opened the window. The street was quiet.

## Chapter 2

At the library, Mara examined a handwritten catalogue while the keeper searched the shelves.
lixity dashboard sample.md --language en -o sample-dashboard.html

Open sample-dashboard.html in your browser. For more informative exploration, use a longer manuscript with several chapters and read the interpretation guide. Analysis defaults to English; use --language de for German or choose --language auto explicitly for heuristic detection.

Optional Zotero Desktop

Install Zotero separately and enable its local API in Settings → Advanced. Zotero 10 or later provides the instance identity required for safe refresh. Run Zotero on the same computer as the Lixity server. No cloud account is needed: Lixity reads the local service at 127.0.0.1:23119. The server dashboard can browse collections and capture selected PDF/text attachments after retention consent. Images, audio and video remain in Zotero. Download cloud-only attachments before capture. Closing Zotero stops browsing and refresh, but already retained evidence remains available in Lixity. Read the capture and migration guide before upgrading an existing archive to v3.

Open an existing project and research archive

lixity serve /absolute/path/to/project --host 127.0.0.1 --port 8765

Replace the example path with your project directory. Open http://127.0.0.1:8765/, then verify the displayed project path and title. Open Project reconnects an existing folder and its research archive. New Project → Import Manuscript creates a separate project from uploaded manuscript bytes; use it only when that is your intention.

For a research-only workspace, an initialized archive can be opened without a manuscript. Source records remain available; comparing sources with manuscript text needs a loaded manuscript.

Since v1.23.0: Research & Dossiers, Manuscript & Analysis, and Project & Settings are separate views. New Project, Open Project and optional guidance remain available in every view. Under Project & Settings, choosing or dropping a manuscript shows its filename without submitting it. Continue to import… opens the existing Import Manuscript dialog; confirmation creates a separate project. Use Open Project to return to the original archive.

Current-main source and dossier lists filter loaded metadata locally; use Research → Search to search retained text. NDA controls start collapsed when the project provides that capability. Embedding hosts with a load capability retain Analyze manuscript now → for their existing manuscript-load action.

Running the server day to day

lixity serve binds 127.0.0.1:8765 by default and is strictly local: no manuscript bytes leave the machine. Every browser tab shares the one running instance. If the port is already occupied, Lixity stops before doing any setup work and prints the conflicting port together with the commands to open, relocate or stop the existing instance — instead of failing with a bare socket error.

For a background instance that survives closing the terminal, use the launcher shipped in the source checkout: scripts/lixity-start.sh on Linux and macOS, scripts/lixity-start.ps1 on Windows. Both provide start, status, restart and stop, keep port-scoped PID files (lixity-<PORT>.pid) under $XDG_RUNTIME_DIR (or %LOCALAPPDATA%), and verify that a recorded PID is still a Lixity process responding on that port. From an editable checkout, make serve and make stop wrap the shell launcher.

Lixity installs no startup service by itself. To start at login, register one of the provided units: a systemd user service on Linux (scripts/lixity.service), a launchd agent on macOS (scripts/lixity.plist), or a Task Scheduler task on Windows. Each needs one edit to point at your lixity binary. Keep these points in mind:

  • The systemd unit takes its port from Environment=LIXITY_PORT= and references it as ${LIXITY_PORT}. systemd does plain variable substitution only — a shell-style ${LIXITY_PORT:-8765} default is passed through literally and would break --port. Override both lines in a drop-in.
  • Do not add ProtectSystem= or ProtectHome= to the systemd unit. The server writes exports/ and the research archive inside the manuscript project directory, so a read-only filesystem breaks it.

Start Zotero as well if you need catalogue browsing or source refresh. Reapply any OCR environment settings before launching Lixity; an export made in an earlier terminal is not persistent configuration. Use Ctrl+C in a foreground terminal to stop the server, or the launcher's stop. Existing research records stay on disk. If port 8765 is already in use, identify the existing server or choose another port; do not stop an unrelated process blindly.

The project exists, but the server cannot open it

The browser's folder chooser shows the filesystem visible to the server process. A container, sandbox or service account can have different access from your terminal. Verify the process user, directory mounts and read permissions. Start the service with the explicit project path and an environment that can access that folder. Avoid creating a replacement project merely because an isolated server cannot see the original.

After changing packages, filesystem access or LIXITY_OCR_WORKER, restart the intended server through its service manager or terminal and verify the project again. Do not start a second server on the same port and assume the browser switched to it.

Using the Python API?

Install Lixity in the consuming project's virtual environment. A uv tool environment is isolated and does not make import lixity available to unrelated Python processes. Pass explicit project configuration when integrating multiple projects.
