Archive sources and import PDFs with local OCR

Lixity's experimental research workspace retains local sources and connects exact passages with dossiers, claims and author decisions. Every operation names a project. Sources remain evidence for human review; an import, citation or integrity audit does not certify their factual accuracy.

Maintained by the Lixity project · Updated 27 September 2026

Import a local source

Start with a source you are allowed to retain. This synthetic example assumes you saved a short note as source.txt. Initialize only a new research archive:

lixity research init --project ./sample-project --title "Sample research" --language en
lixity research ingest --project ./sample-project --file ./source.txt --allow-retention --origin-url https://example.org/archive/source
lixity research reindex --project ./sample-project
lixity research search --project ./sample-project --query "reading room"

--allow-retention confirms your permission to keep source bytes locally. It neither grants redistribution rights nor makes a claim true. Avoid importing sensitive sources into public repositories.

In the dashboard, open Research → Sources, choose a text or PDF file (or paste text), enter an optional title, tags and origin URL, then explicitly confirm retention. Import locks the button while processing. Successful import clears the form; rejected submissions retain it for correction.

What does the origin URL do?

The optional field records the source's original HTTP(S) address alongside the retained capture. It is metadata only: Lixity does not fetch the URL, monitor changes there, or verify the site's identity. Credentials and whitespace are rejected. Do not paste a private access token or signed download URL into provenance; use a stable public source address where appropriate.

The URL appears in source details and citation context. It remains separate from the title, source-critical notes and tags. Identical URLs do not merge sources. If you refresh a named source with a new URL, Lixity creates a new capture; earlier citations keep their original text and provenance.

URL-bearing captures use research-local/2 and a v2 manifest. Existing archives remain unchanged until a write needs the new format. Older installations cannot read these source records; make a full backup before upgrading and keep all writers on a compatible build.

Use Zotero as the source and media catalogue

Included in v1.19.0: the optional Zotero Desktop bridge browses an explicit local library and its collections from Research → Sources. Inspect an item, choose a PDF/text attachment and confirm retention to capture evidence. Open originals in Zotero or explicitly refresh linked sources. Images, audio and video remain in Zotero; no transcription or visual analysis is provided.

Structured attachment identities prevent duplicate captures and require research-local/3 with a v3 manifest. Older readers reject this format. Changed captures require explicit refresh; old quotations remain intact. Metadata-only PDF refresh reuses extraction when original bytes are identical. There is no background synchronization.

For existing sources, research zotero-export produces an additive RIS bundle with retained files, identity tags and provenance. Import and review it in Zotero, verify the exact original bytes, then bind the existing Lixity sources. Export does not delete or replace the archive. See the setup, migration and compatibility reference for the complete procedure.

Find the current authored position

Included in v1.19.0: the dashboard Search tab includes sources, current dossiers, claims and decisions, with a selector to narrow the search. Authored hits show their type and revision; View details opens the existing revision viewer. Only source passages can be cited as evidence.

lixity research reindex --project ./sample-project
lixity research search --project ./sample-project --query "inspector" --scope all
lixity research search --project ./sample-project --query "inspector" --scope decisions

The CLI defaults to source passages when --scope is omitted. Search matches words in current records, not their history. It does not resolve ambiguous names, reconcile contradictory statements or decide whether a proposal is final. Keep a concise character dossier with separate decisions, proposals and open questions, linked to supporting research.

Does PDF import include scan OCR?

A PDF with selectable text can use local Poppler tools. An image-only scan needs a separately configured self-hosted OCR worker. Installing Lixity does not download a model or launch an inference service. The configured worker controls its own resource use and network behavior.

lixity research ocr-status
lixity research ingest --project ./sample-project --file ./document.pdf --allow-retention
Diagnostic statusMeaning and next action
native_onlyPoppler tools are available. Text-layer PDFs can be extracted; scans need an OCR worker.
readyAn executable worker and pdftoppm were found. This is a configuration check, not a model-integrity or recognition-quality test.
partialPage rasterization is unavailable. Install pdftoppm before relying on multi-page extraction.
misconfigured_workerThe configured executable was not found or cannot run. Check its path and permissions in the server environment.
missing_dependenciesInstall Poppler for local PDF text extraction; configure a worker separately for scans.

On Debian/Ubuntu, the package is poppler-utils; on macOS with Homebrew, it is poppler. Verify that pdftotext and pdftoppm are on the server's PATH. The browser diagnostic follows the selected interface language; CLI JSON uses stable status codes and English guidance.

Connect an existing self-hosted worker

Baidu's official inference tools do not implement Lixity's worker JSON protocol. A separate adapter is required. The Unlimited-OCR integration guide compares the official runtimes, verified source pins and remaining limitations; no model server or adapter is bundled.

Set LIXITY_OCR_WORKER to a single executable path, not a shell command with arguments. The worker receives one argument: a temporary JSON request-file path. It returns JSON on stdout with text blocks and physical page numbers. Lixity applies a 120-second worker timeout and may fall back to the native text layer if the worker fails. Read the worker interface and limitations before building an adapter.

export LIXITY_OCR_WORKER=/absolute/path/to/ocr-worker
lixity research ocr-status
lixity serve /absolute/path/to/project --port 8765

These are POSIX-shell examples. Set the equivalent process environment for your service or Windows shell. Restart the server after changing its environment. Test an authorized synthetic scan and inspect the extracted quotation against the page; an executable check alone is not an OCR acceptance test.

Original PDF bytes and extracted UTF-8 text are stored separately by checksum. The current archive cites character spans in extracted text; worker page boxes, model attestations and recognition confidence are not a persisted, audited page-citation contract. Always consult the original PDF when exact visual evidence matters.

Back up and test restoration

The authoritative data lives in the project's research/ directory. The SQLite search catalogue is disposable and is not a backup. Keep archives outside public Git repositories, ideally while no writer is running.

lixity research export --project ./sample-project --output ./sample-backup.tar.gz
lixity research restore --from ./sample-backup.tar.gz --to ./restored-sample
lixity research audit --project ./restored-sample
lixity research reindex --project ./restored-sample
lixity research search --project ./restored-sample --query "reading room"

Restore into a clean target. Restoration checks archive member paths, checksums and record relationships before placing the store. Resolve a known passage ID afterward to confirm that the expected quotation and origin URL survived. Audit success concerns stored integrity, not historical truth or permissions.

Included in v1.19.0: research zotero-backup pairs the research archive with an explicitly selected, closed Zotero data directory. research zotero-restore verifies the file inventory and checksums before restoring both into a new directory. It never overwrites a working library. Manuscripts, application profiles and external linked attachments require separate backup. Consult the command reference before relying on the pair as your recovery plan.

Input and research limits

Text inputs must be nonempty UTF-8 without NUL bytes, at most 2 MiB; PDFs are at most 50 MiB. Both imports are limited to 5,000 nonempty extracted passages. Search is lexical SQLite FTS5/BM25, not semantic retrieval or translation. A source refresh does not update authored claims or decisions automatically.

See the implemented research reference for CLI/API details. The broader research RFC includes unimplemented interfaces. Read metric interpretation before comparing a source with a manuscript.
