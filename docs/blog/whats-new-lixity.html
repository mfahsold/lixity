What's new in Lixity: numbers you can compare, evidence that survives edits

Posted 16 October 2026 · 7 minutes · Blog

BlogFirst lookInterpret resultsExample analysis

Lixity is a local-first manuscript analysis tool: it reads a novel on your own computer, shows the rhythm, vocabulary, dialogue and tense behind every result — and keeps the research behind your decisions in one workspace. This release line is about two kinds of trust: numbers you can actually compare, and evidence that does not silently rot while you edit.

Comparable or marked, never guessed

Small chapters used to produce big-looking statistics. A three-sentence stage note could outrank a full chapter in a z-score table simply because short samples are noisy. Comparisons now use documented floors:

  • Chapters below 100 words (MIN_COMPARABLE_WORDS) get no z-scores, effect sizes or FDR marks.
  • Sentence-distribution features (staccato, cascade, sentence CV, start entropy, first-person starts) need at least five sentences (MIN_COMPARABLE_SENTENCES).
  • Showing/telling comparisons use the same word floor and mark short chapters as not comparable instead of inventing a ranking.

Where a value is withheld, the interface says why — the panel explains the minimum in all seven supported languages instead of hiding the reference silently. Recompute older reports before comparing: the numbers above are honest now, not retroactively patched.

A smaller fix with the same intent: sentence segmentation no longer merges across blank-line blocks. A salutation, a stage note or a sign-off stays one unit; chapter ASL, scene units and the corpus sentence statistics finally agree on every count.

The dashboard notices when your manuscript changed

The local dashboard now checks the manuscript digest when the page loads. If the file changed on disk since the last build, it rebuilds itself instead of presenting yesterday's numbers with today's confidence. No more quietly stale chapter counts.

Evidence anchors that tolerate editing

Research links between a source quote and a claim or decision are stored as exact anchors: quote, paragraph hash, line span, offsets. Editing is normal, so the review state now distinguishes two cases:

  • Edits outside the quote (the quote still appears exactly once, the paragraph moved or grew): the link is marked adjusted and can be re-pinned in one step — via the review tab or lixity research reconcile-manuscript --accept-moved. The refreshed line span, hash and offsets become a new link revision.
  • Edits inside the quote: the link is changed and stays in review. Lixity never re-pins automatically, because only you can decide whether the meaning survived.

Chronology entry also got friendlier: a plain hyphen between four-digit years (1929-1933) is now accepted as a same-precision range next to the typographic dashes.

A quieter research workspace

The research workspace keeps sources, dossiers, claims, decisions, evidence links and review markers. Recent polish:

  • The timeline is a view, not a planet: it lives as a List/Timeline switch inside Claims & evidence, next to the entries it orders. The decisions pane states its scope — deliberate choices with a rationale, not historical claims.
  • Zotero stays a catalogue, visibly. Cards show a quiet Zotero ↗ link, a type line, and metadata as a proper card; tags are clickable and filter the list. Capturing a source into the archive remains an explicit act.
  • Evidence panels keep their loaded citations when other lists refresh — the panel state lives in the list model instead of being rebuilt under you.

One interface, one cast

The interface had grown a decade of small decisions: ten border radii, fifteen font sizes between 0.72 and 0.84 rem, three spinner recipes, two tab languages. The current main branch replaces that with a small, enforced system:

  • One scale in the design tokens (radius, type, spacing, colour) — used by the app and the staged documentation site, not copied.
  • One control language: the workspace switch and the research sub-tabs share one tab recipe, badges and tags are one pill family, and compact controls keep the 44 px touch minimum on touch devices.
  • A component layer (vendored Preact, no build step, CSP-compatible without unsafe-eval) now renders the list panels. That fixed a real bug along the way: the server-rendered “Loading…” placeholder no longer lingers beside the loaded list.
  • The visual-consistency browser suite fails when control radii, badge shapes or sampled text sizes leave the scale — the system cannot drift back into one-off values.

Logging you can actually find

Diagnostics now run through one logging tree with a single UTC format and standard levels. The managed service appends to service-PORT.log, and starting an oversized log rotates it (.1–.3) so it stays bounded. --debug, LIXITY_DEBUG and LIXITY_LOG_LEVEL control the level; lixity service status prints the log path. Request logs keep the route without its query string, so research context and project tokens stay out of the file — and log records never contain manuscript text.

Security baseline, written down

The dashboard shell carries a per-response nonce Content Security Policy (default-deny scripts, inline styles only), Cross-Origin-Opener-Policy and a Permissions-Policy denying device APIs. Loopback bind, Host allow-list, Origin guard, payload and artifact limits and explicit non-goals are documented in the repository's SECURITY.md. Nothing about your manuscript is uploaded: analysis and research stay on your machine.

Try it

  • Three-minute first look — chapter comparison, a passage and its measurements.
  • Effi Briest and Pride and Prejudice — complete public-domain analyses in the browser.
  • Install: uv tool install --python 3.12 --managed-python lixity, then lixity service start --open.

The statistical signals support a human review — they are not a quality score, and they are not an instruction to rewrite prose. That has not changed, and it never will.
