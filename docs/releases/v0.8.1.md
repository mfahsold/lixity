# Lixity v0.8.1

Release date: 16 November 2026.

## Writing and close reading

- Write and read in one local workspace with undo, autosave, search/replace,
  explicit draft comparison, conflict detection and recovery. Revision analytics
  follow current source bytes after reverts or external edits while retaining
  immutable historical measurements.
- Use the formatting bar, direct-speech reading, counted-text evidence and chapter
  comparisons with localized controls. Sticky navigation keeps destinations visible.
- Import a Word/DOCX copy with a preview and explicit destination. The original
  remains protected, including aliased paths.

## Research beside the manuscript

- Keep five content areas: Dossiers, Claims & evidence, Timeline, Decisions and
  Sources. Shared search and link review retain the selected content and drafts.
- Compare vocabulary from a selected source, inspect shared terms and chapters,
  then return to its reader. Exact retained quotations stay distinct from the
  current full source; word overlap does not establish factual support.
- Organize collections by dossier title and reading order. Create explicit
  manuscript-derived character/scene dossier drafts and inspect linked evidence,
  author decisions and unresolved manuscript associations.

## Audio, exports and onboarding

- Review speech direction and recordings through the existing optional workers
  and configured providers. Jobs settle after temporary source cleanup, including
  late cancellation and shutdown.
- Share selected research in PDFs or reading websites, with optional existing
  chapter recordings. Reader-progress controls are not access protection.
- Explore the expanded browser sandbox and the paced 48-second product tour.
  Central descriptions and documentation clarify local analysis, optional
  network adapters, heuristic limits and availability in seven languages.

## Security and integrity

- Use exclusive loopback listener bindings on Windows and canonical temporary
  paths for cross-platform example generation; preserve POSIX listener behavior.
  Preserve reviewed demo source bytes across Git checkouts so pinned audio
  provenance is identical on every platform.

- Encode Markdown callout and wikilink attributes so quoted input stays inert.
- Bound DOCX source size, ZIP entries, decompressed XML and converted output;
  reject original-file aliases and publish conversions atomically.
- Require the complete declared file inventory when restoring research archives,
  before migration/publication. Checksums establish integrity, not authorship.
- Keep startup list reads bound to their project context; stale responses cannot
  strand collection editing or erase accepted drafts.

## Verification and distribution

Keep logging imports and the zero-MAD statistical fallback compatible with
Python 3.10. The complete source CI gate runs on Python 3.10 and 3.12.

The release pipeline checks the exact tagged source and browser UI before
building, smoke-installing and attesting the wheel and source distribution.
GitHub, PyPI and Pages use the same verified release. Zenodo archival is
asynchronous and its version DOI is verified separately.

```bash
make release-check RELEASE_TAG=v0.8.1
make browser-full
```
