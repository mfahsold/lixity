# Lixity 1.16.0 — integrated projects, research and numerical corrections

Lixity 1.16.0 brings the local project workflow and experimental research archive
into one dashboard. It also corrects core statistical calculations and strengthens
project isolation, localization and error recovery. The package remains
source-available under LNCL-1.0 for non-commercial use.

## Project and research workflows

- Start with `lixity serve --no-project`, create a localized template, import a
  manuscript, or open an existing manuscript/folder with its research archive.
  Import and opening are explicitly separate operations. An empty manuscript or
  initialized research-only folder does not hide its archive.
- Inspect source text and supplied source context, read full dossiers with
  citations, and select search passages for a dossier or claim without copying IDs.
- Create claims with scope and confidence, attach supporting/contradicting evidence,
  and record author decisions with their rationale and dramatic impact. Confidence
  and deviation fields record judgments; they do not certify factual accuracy.
- See the active archive root and record counts. Unavailable, uninitialized and
  empty archives have distinct states. Failed project actions keep the form and
  entered values visible; imports cannot overwrite an existing manuscript.
- Keep historical evidence chains readable after source withdrawal or purge.
  Deleted passage references become content-free tombstones, with explicit
  unavailable citations instead of broken archive validation or retained quotes.
- Use the same research operations from the CLI and Python API. Retention requires
  explicit permission; source bytes are not uploaded to a remote service.

The research API is an **experimental local pilot** using `*-local/1` envelopes.
External OCR, Zotero synchronization, vector retrieval and archival interchange
remain planning items. See the [implemented commands and limits](../research/USAGE.md).

## Analysis quality and language support

- Chapter-to-rest Jensen–Shannon divergence now uses the correct missing-type
  probability mass. Unequal chapter sizes no longer create negative divergence
  for identical distributions. Values use natural-log units in `[0, ln(2)]`.
- Prose token, syllable and dialogue counts exclude Markdown headings consistently
  with sentence measurements, so changing chapter titles does not change readability.
- Dunning G² keyness includes both term and non-term cells. Research comparisons
  use a consistent prose scope and explicitly report differing language profiles;
  shared vocabulary does not establish factual support.
- Source details verify retained bytes before returning quotes, just as citation
  retrieval does. Corrupted source storage produces an error instead of a quote.
- Reports use the conventional sentence-length median. The additive
  `median_sl_exact` field exposes it; the legacy integer `median_sl` retains its
  original upper-middle semantics for compatibility.
- English remains the default, with explicit automatic language detection.
  Project settings follow the selected project, and import preserves the chosen
  language. All seven profiles cover the project/research interface and templates;
  English and German have the most developed linguistic resources. Shared
  mathematical estimators remain language-neutral.
- TOML project settings now work on Python 3.10 through a conditional `tomli`
  dependency. Python 3.11+ uses the standard library. Research search requires
  SQLite with FTS5; no model downloads are needed.

## Updating and compatibility

Install the release in an isolated CLI environment:

```sh
uv tool install --force --python 3.12 "git+https://github.com/mfahsold/lixity.git@v1.16.0"
lixity --version
lixity serve --no-project --language en
```

Restart an existing local server after updating. Opening an existing project
selects its original directory; selecting manuscript bytes in the import tab
creates a separate project. Follow [Onboarding](../ONBOARDING.md) for both paths.

Analysis and style schema versions remain **2 and 4**. Numeric corrections change
some results: recompute older analyses before comparing them with 1.16.0. The
exact median is additive; consumers can continue reading the legacy integer.
Research records retain their explicit project identity and source provenance.
The experimental source-analysis limitation code `historical_language` is replaced
by `original_language_supplied`: supplying an original language does not establish
that a source uses a historical variety. Comparison responses add
`meta.lexical_comparable` and `comparison_limits` without removing existing scores.

Verification covers Python contracts and numerical regressions, real local-server
project/research workflows, and rendered desktop/mobile states in all seven UI
languages. The suite uses synthetic or public-domain material. Passing tests do
not establish linguistic accuracy across every language or historical truth.
