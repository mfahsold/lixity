# Lixity 2.4.0 — Manuscript PDF downloads and research reading

Create a manuscript PDF in the native workspace from the top of **Manuscript &
Analysis**. In **PDF export**, choose **A5 reading copy** (default),
**A4 manuscript sheets** or **A4 analysis report**, then select **Download PDF**.
The same composer serves the CLI and
the browser. It reads the selected file when requested and returns a PDF
attachment without creating server export files or changing the manuscript or
research archive. An opaque metadata token rejects changed selected context;
it is not a content-version lock. Standalone HTML remains read-only without a
PDF download action. NDA PDF generation is a separate workflow.

**Dossier alongside** opens an optional, focused reading view. Choose a dossier,
or open a chosen dossier from its card. The existing manuscript chapters, search
and filters remain on the left while the dossier reader appears on the right;
other analysis panels are temporarily hidden. Closing restores those panels and
retains manuscript state. Reading makes no writes or automatic evidence links.
The selection lasts for the current page; refresh explicitly for the latest
saved dossier revision. Desktop panes scroll independently; at or below 900
pixels the dossier sits above the manuscript. Context-bound reads use an
optional token on the existing dossier endpoint, retaining legacy calls and JSON.

Selected text within one uniquely resolved source paragraph can prepare the
existing claim evidence-link form. The draft shows the selected quote and the
complete retained paragraph before the author chooses a claim, relation and
optional rationale and saves separately. The saved citation still pins that
whole paragraph and source version. Cross-paragraph or ambiguous selections are
unavailable; whole-passage actions remain in the Passages view. Selection and
draft preparation create no records and introduce no sentence-level citation
format.

Research CLI commands using an existing archive may omit `--project` only when
the current working directory itself validates as an initialized research
project. Explicit `--project` arguments remain authoritative. There is no parent,
environment, global-setting or last-opened-project fallback. `init` still names
its project; restore commands keep `--to`, and `schema`/`ocr-status` retain their
interfaces. Python and HTTP research APIs remain explicitly scoped.

`research link PASSAGE_ID CLAIM_ID` is a create-only shortcut using full returned
IDs in that order. It defaults to `supports`; `contradicts`, `qualifies` and
`contextualizes` remain available with optional rationale, reviewer and actor.
It reuses the existing evidence writer and JSON output. `link-evidence` remains
available for creation, inspection and revisions.

The **Author review state** field uses **Author assumption**, **With evidence**
and **Disputed** to describe the author's assessment of support.
Stored `hypothetical`, `evidenced` and `disputed` values, immutable paragraph
citations and archive/JSON contracts remain unchanged. Neither the labels nor
links establish historical certainty, calculate a probability or rewrite prose.

Validation uses synthetic archives and manuscripts: initialized-cwd selection
and explicit overrides, positional link semantics, whole-paragraph citation pins,
stale-context rejection and read-only companion behavior. Browser checks cover
the seven interface languages at desktop and mobile widths. PDF checks use
native parser/font inspection and extracted-text round trips; these do not establish
font coverage on every host.

See the [PDF reference](../USAGE.md#download-a-manuscript-pdf-since-v240)
and [research workflow scope](../research/USAGE.md#reading-and-cli-workflows-since-v240)
for controls, compatibility and limits.
