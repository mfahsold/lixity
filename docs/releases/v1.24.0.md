# Lixity 1.24.0 — Scene registers and clearer research review

Lixity 1.24.0 adds scene comparisons, guided revision review and optional local
OCR. Measurements remain descriptive: they support a reading of the text,
not an automatic quality verdict or an instruction to rewrite it.

## Compare scenes in their intended register

- The API, terminal and dashboard report the same 16 features for each scene.
  Without explicit dividers, chapters serve as scenes. Headerless drafts retain
  all their prose and original paragraph lines.
- Assign registers and optional target ranges in your project's settings.
  Each register gets its own manuscript-only median and MAD; research sources
  never enter these references. No novel-specific or genre targets are built in.
- Word/sentence counts explain the available data. HD-D uses 0–1 and is
  unavailable below 100 tokens; sentence variation needs two sentences.
  Approximate standard errors are not validated confidence intervals. Zero
  plug-in errors are withheld rather than presented as certainty.
- Shared configuration and chapter boundaries keep reports aligned, including
  custom whole-line headings and LF/CRLF files. Already measured chapters are
  reused in display reports. Terminal values use the shared localized labels,
  units and number formatting.

See [scene settings and limits](../USAGE.md#scene-registers-and-project-targets).

## Review research changes before saving

- Conflicting drafts retain their text and reason. A read-only three-way
  preview compares the original, current and proposed values; you explicitly
  choose overlapping changes, then save separately.
- Queue related dossier, claim, evidence-link and decision revisions in one
  change set. Inspect or edit each draft, then save the set together. Invalid
  changes and stale snapshots accept none. Browser drafts disappear on reload;
  an uncertain network result requires checking history before retrying.
- Decision impact and **Review** follow recorded links, dates and revision pins.
  Historical pins may be intentional. These views do not detect semantic
  contradictions, establish facts, identify every affected passage or rewrite
  documents.
- Section reads and edits share nested boundaries, preserve unrelated text and
  line endings, and reject ambiguous headings. Existing dossier revision pins
  are preserved when an associated list changes.
- Source/audit reports offer bounded text or Markdown and an optional interactive
  pager. Complete JSON remains the default for existing commands. Safe terminal
  text uses the common formatter, without coupling analysis to research.

See [research workflows](../research/USAGE.md#research-workflows).

## Choose local OCR

Locally installed Tesseract can recognize scans without a separate worker
service. Select `LIXITY_OCR_BACKEND=tesseract` and installed language data with
`LIXITY_OCR_LANGUAGES` (default `eng`), then restart the server. Diagnostics
identify missing language data and failed startup probes. Nothing is installed
or downloaded automatically. The external worker and native-only defaults stay
available; native fallback still requires an explicit choice after OCR failure.

New native captures identify `poppler-native/1`; local Tesseract captures identify
`tesseract-cli/1`. Both require **research activity/manifest v4**. Older readers
reject these archives, so use a compatible reader and retain a backup. Existing
v1–v3 records and cached provenance remain unchanged; successful external worker
captures keep their established identifiers. Timeouts reject partial captures;
mixed-PDF warnings still need inspection against the original pages.

Validation exercised real native Poppler extraction and a synthetic Tesseract
executable for language checks, invocation, errors and timeouts. Real Tesseract
recognition accuracy and an external model runtime were not verified here.
Test a permitted scan in your own environment before relying on its quotations.

See [local OCR setup and compatibility](../research/USAGE.md#use-local-ocr-without-a-worker-service).

## Compatibility and maintenance

Analyze/profile JSON stays at schema 2; style passports stay at schema 4.
Scene reports add their own schema 1 envelope. Research preview, batch and
editorial reports have separate versioned envelopes; existing strict revision
and JSON interfaces remain available.

Deprecated HD-D sampling arguments remain accepted and ignored with a warning;
their previously announced v1.24 removal is deferred. Omit them when using the
exact estimator. The deprecated matrix wrapper also remains available; use
`claim_matrix_data()` and `render_claim_matrix()` for new integrations.

README and Pages keep six contextual feature examples, responsive layouts,
full-size image links and a shared guide theme. Documentation is English;
German remains the first focus for linguistic resources, while analysis defaults
to English. CI avoids duplicate test matrices and checks exact wheel filenames
and bytes. Updated action runtimes remove the upstream Node/punycode warnings.

Release checks cover warnings-as-errors tests, lint/type checks, documentation
links, desktop/mobile Chromium workflows and isolated wheel installation.
Examples and screenshots use synthetic or public-domain content, not private
manuscripts or source archives.
