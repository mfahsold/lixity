# Lixity 2.3.0 — Clearer manuscript review, search and PDF export

Explore the public, read-only example before installing Lixity. Six invented
chapters demonstrate chapter contrasts, paragraph reading, filters and the 3D
view. The report uses the shared analysis engine with explicit defaults and
accepts no uploads or edits. It is an illustration, not a benchmark or a
literary-quality assessment. The three-minute guide introduces the workflow and
the developer's own experience using Lixity while writing a debut novel.

The local welcome guidance starts with choosing a manuscript, confirming its
preview language and reading a passage. **Analyze a manuscript** opens the
existing import dialog; it does not submit the file automatically. Optional
research and further-analysis guidance starts collapsed. Loaded manuscripts
show **Start your review** before the KPIs, with direct routes to a source
passage, available chapter comparison and sentence rhythm. The passage route
starts with the first paragraph in source order meeting the selected tense-flag
threshold, or the opening when none does; it clears filters and focuses the
source text. These entrypoints reuse existing measurements without a quality
ranking or automatic editorial action.

Opened paragraphs show manuscript text first, followed by source lines and
measurements in a compact native **Values** disclosure (**Werte** in German).
Marker actions follow the passage. Closed paragraph contents are created when
opened with JavaScript enabled; the complete text remains embedded and is
readable in the static fallback without JavaScript. The style heatmap, reference,
dimensions and structural diagnostics share one keyboard-accessible tabbed area.
Existing panel and feature anchors reveal the appropriate tab before navigating.

Manuscript search checks all paragraph text, including unopened paragraphs. It
uses case-insensitive substring matching, with a count, next/previous controls,
`Enter`/`Shift+Enter` navigation and `Escape` to clear. Active search takes priority
over the flagged-only filter; clearing it restores the selected filter. Text that
resembles markup remains inert. Search and analysis navigation work in the
self-contained offline HTML; lazy paragraph rendering reduces initial DOM work
without removing growth in the embedded manuscript and measurement payload.

`lixity research dossier-image` retains a permitted local PNG/JPEG and attaches
it to a dossier in one atomic operation. It requires the explicit project,
dossier ID, reviewed snapshot/revision and `--allow-retention`. Optional section,
caption, alternative text and source context reuse the Web/Python API. Existing
16-MiB/64-million-pixel limits, immutable version pins and stale-edit protection
apply. No OCR, remote download or factual verification is added.

`lixity pdf` composes three documents from the manuscript and its analysis: an
A4 analysis report, an A5 reading layout with a serif measure and chapter
openings, and an A4 submission sheet of at most 30 lines per page and 60 characters
per line.
Rendering is self-contained: there is no browser, converter or runtime font
package, and no new dependency is added. Fonts are found on the host and
embedded as TrueType subsets with composite-glyph closure for characters covered
by the chosen fonts. Output carries a `ToUnicode` map,
so the text stays searchable and copyable. A font licence that forbids
embedding is refused instead of producing blank pages, and a missing font is
reported with the paths searched. Unsupported drawn characters report their font
role and Unicode codepoint. Page-number digits are included even if absent from
the manuscript; overlong words and final lines fit within the page measure without
dropping characters, and justified text applies negative word spacing correctly.
Default report fonts prefer DejaVu Sans regular/bold for generated analysis
symbols. Explicit font choices remain supported. Output is written beside the
manuscript unless another path is selected. The renderer has no automatic
mixed-script fallback, contextual shaping, bidirectional layout or PDF/X
production preflight. See the [PDF reference](../USAGE.md#lixity-pdf) for options
and limits.

Source-context JSON supplied to `ingest` or `dossier-image` must be an object,
whether inline or in a local file. Invalid scalars, arrays and null are rejected
through the normal CLI error channel without accepting a capture. Omitted
context and empty objects remain valid. This tightens invalid-input handling;
valid API/CLI JSON contracts and archive formats are unchanged.

Bash/Zsh research command names now come from parser metadata instead of a
separate partial list. The security policy links to the current release, and
image guidance distinguishes generated visual references from documentary
evidence. Long research titles stay within their cards on mobile, and the opening
guide explains how the browser's active project differs from CLI work.
Licenses and personal-project manuscripts are unchanged.

Research lists coalesce pending reads and ignore superseded responses. Unchanged
cards retain opened source/dossier details while refreshed or removed records
update deliberately. Rendering reconciles lists in linear time. OCR page
timeouts remain within the original configured budget despite floating-point
deadline rounding, and still expire across multiple pages.

Default nominal-suffix counts now exclude the language's curated function words
in corpus, chapter and paragraph measurements. Explicit regex overrides retain
their original match semantics; JSON schemas are unchanged. This changes some
measured values, so regenerate older reports before comparison. These remain
suffix heuristics, not part-of-speech tagging. Short-paragraph density guidance,
compact unavailable show/tell states and neutral marker wording explain the
limits without inventing scores for insufficient data.
API diagnostics retain method, URL, HTTP status and duration, without copying
response contents into the browser console.
