# Lixity v0.7.7

Released 28 October 2026. This release brings the work since v0.7.6 together
across manuscript analysis, human review, reading exports and experimental audio.

## Voice, direction and listening copies

The CLI and native workbench share project profiles, source-bound passage
direction, explicit pauses and preview plans. VoiceDesign creates a voice from a
description, but independent generations need not sound identical. A separately
installed Qwen3-TTS 1.7B Base worker can instead reuse an explicitly chosen,
project-local WAV reference and its exact transcript. Assign profiles to
passages deliberately; Lixity does not infer speakers. Base rejects free-form
delivery instructions, rather than silently discarding them. References contain
private audio and text and must be backed up with the project. Existing versions
without Base support reject the new engine. Listen to short previews before a
long render; model output and accent are not guaranteed.

An FFmpeg postprocessing factor adjusts synthesized speech without changing
explicit paragraph or scene pauses. New implicit profiles use 1.2; existing
explicit and omitted saved values retain their prior meaning. `--speed` overrides
all profiles for one CLI render. Cached model segments remain unmodified and can
be reused at another tempo. Non-1.0 tempo requires FFmpeg on the rendering host.

## Reading and review

The project view groups work by purpose. Profile editing, passage direction and
audio output have separate entry points. A flagged passage links to its existing
review decision; unmatched decisions for the current manuscript remain stored
and visible as a count. A renamed manuscript has a different path and is not
silently matched to old decisions. Reading websites can explicitly expose selected
chapter or language measurements, or a fuller analysis within the chosen chapter
scope. Review the exported content before sharing.

## Analysis and evidence

The German default tense heuristic no longer treats arbitrary `-te/-ten/-test`
endings as past-tense evidence. Some unlisted past forms remain undetected;
previous decisions may require review. Zero-MAD comparisons, missing chapters
and insufficient showing data no longer produce invented standardized values.
Order diagnostics and FDR selection remain exploratory and are not calibrated
literary error probabilities. The normal-model threshold expectation is labeled
as a model reference rather than an observed error count.

Reproducible optional evaluations compare Italian and French syllable heuristics
against separately obtained lexical resources and German quotation cues against
historical, annotated REDEWIEDERGABE excerpts. These comparisons expose tradeoffs;
they do not establish accuracy for contemporary novels or other languages.
The UD feature checker also reports aligned finite-verb false positives and
misses independently from the existing gold-verb tense-feature denominators;
alignment omissions are visible and it does not validate literary verb groups.
Analysis signals support a human reading, not a literary quality verdict.

## Release and compatibility

Tagged publication now runs the reusable full source and browser checks on the
same commit before publishing. Local release checks and cross-platform checks
remain separate. For supported installations, use `pip install --upgrade lixity`;
an installation with a historical version higher than 0.7.7 needs an explicit
version selection. See the [installation guide](https://mfahsold.github.io/lixity/INSTALLATION.md)
and [measured limitations](https://mfahsold.github.io/lixity/STABILITY.md).
