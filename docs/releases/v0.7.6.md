# Lixity v0.7.6

Release date: 27 October 2026. This release collects the completed changes since
v0.7.5 across the shared engine, CLI, local workbench and reading exports.

## Shared audio pipeline and local execution

`lixity read-aloud` and **Audio & voices** use the same validated project profiles
and synthesis backend: optional Qwen3-TTS 1.7B CustomVoice, preset voices,
explicit supported delivery instructions, literal pronunciation replacements and
paragraph/scene pauses. CLI overrides do not rewrite saved profiles.
Piper, its cached-voice controls and precise speed flags are removed. Existing
Piper profiles require an explicit Qwen preset choice through `audio-migrate`;
preview is read-only and application requires a reviewed snapshot and a new
configuration backup outside the project. Voice timbre and precise speed are
not silently translated. Manuscript bytes remain unchanged.

```sh
lixity read-aloud --project ./novel --profile narrator --chapter 2 -o chapter-2.wav
lixity read-aloud --project ./novel --profile narrator --speech-target jetson --chapter 2 -o chapter-2.wav
```

Local CPU operation retains the full Qwen checkpoint. A configured Jetson can
run the talker on CUDA and explicitly decode audio on CPU when shared memory is
limited. Workers, checkpoints and the SSH forward are separate operator-managed
resources; the app does not download weights, start a remote service or silently
fall back to a different engine. Cloning and VoiceDesign are not implemented.
Worker-only attention and codec chunk controls support explicit hardware tuning
of the same model. Inference mode avoids training bookkeeping; resolved runtime
metadata identifies device/dtype/threads/attention/decoder placement. Smaller
decoder chunks retain the upstream context algorithm and do not guarantee a
whole-model memory bound.

Native chapter jobs have progress, cancellation, stale-source guards and temporary
downloads. Completed Qwen segments survive interrupted renders in a bounded private
project cache shared with the CLI; `--fresh-audio` and `--no-audio-cache` make reuse
explicit. Final WAV/MP3 publication is atomic and rejects failed/missing segments;
MP3 requires FFmpeg. Valid audio encoding is not proof of pronunciation or
narration quality. See [setup and limits](https://mfahsold.github.io/lixity/USAGE.md#lixity-read-aloud).

## One local app, independent project tabs

The ordinary app at one origin retains independent project views under scoped
`/w/<id>/` URLs. Opening another project no longer replaces every tab's context.
**App and audio** lists open views, actual worker model health and the bounded
shared audio FIFO (one active job and at most three waiting jobs). Project-bound
jobs/downloads remain isolated across views, including the same project in two
tabs. Up to 16 views are retained. View URLs expire after a server restart;
reopen projects from the home address instead of reusing an expired URL.

## Optional grammatical tense analysis in seven languages

Explicitly installed local syntax models for de/en/fr/es/it/pt/nl can replace
lexical tense cues with contextual
verb-group composition. The shared backend distinguishes perfect/pluperfect,
passive, future, subjunctive and unresolved constructions. It recognizes `übt`
and excludes adjectival `feuchten`/`kunstvollsten` on the tested examples. Scope can
include all predicates or exclude recognized quotations, including multi-paragraph
quotes within one chapter. Corpus, scenes, paragraphs, CLI and evidence use the
same composition. There is no inference-time download or silent regex fallback.

```sh
lixity profile draft.md --language de --tense-model de_core_news_md --tense-scope narration
```

French and Italian have explicit CPU Stanza profiles; the other initial
choices use spaCy. Scientific token-feature checks use 700 official UD2.18 test
sentences, separately from synthetic verb-group construction tests. Missing Mood
is retained explicitly, rather than certifying an indicative interpretation.
This requires optional dependencies and an explicitly installed model; existing
projects retain lightweight patterns until configured. The initial recommended
CPU model matches 39 of 40 synthetic construction cases; an imperative and a
separate literary adjective/verb ambiguity demonstrate remaining parser errors.
This is not a representative accuracy estimate or automatic narrator attribution.
The passage card shows exclusions/unresolved forms and navigates verified original
cue ranges. Existing saved decisions are rechecked under the new policy/model
identity. See [installation](https://mfahsold.github.io/lixity/USAGE.md#grammatical-tense)
and [measured limits](https://mfahsold.github.io/lixity/STABILITY.md#grammatical-tense).

## Verified pipeline and numerical corrections

- Audio segmentation preserves sentence boundaries after whole-paragraph
  pronunciation replacements, without dropping text or adding fragment pauses.
- External FFmpeg conversion has a one-hour direct-child deadline;
  timeouts preserve an existing completed export and clean temporary audio.
- Pure language rules, syntax adapters and scoped measurement/cache orchestration
  have separate owners; the modular refactor preserves exact verb-group results.
- Nested coordination retains shared auxiliaries without crossing a finite
  conjunct; malformed syntax graphs fail explicitly. Reapplying view settings
  preserves its selected grammar model without writing temporary overrides.
- Lag-1 sample autocorrelation remains stable at finite extreme scales/offsets
  and returns unavailable for genuinely constant decimal samples.
- Near-null Dunning G² retains tiny nonzero likelihood-ratio divergence using
  exact integer residuals and a centered deviance series. Independent Decimal
  oracles verify these changes; they do not establish calibrated literary scores.

## Reading, analysis and publication

- Clearer passage tools, exact counted evidence and independent Analysis/Counted
  text/Paragraph comparison controls preserve the continuous manuscript.
- Shared chapter measurement views, wrapping overview navigation, stable hover
  help and responsive paragraph actions work across the localized interface.
- DOCX import has explicit preview/conversion boundaries; mobile paragraph linking,
  term chapter selection and dossier media galleries use existing shared flows.
- Native and reading-site adapters share supplementary report assembly and passage
  research context. Curated reader/companion exports omit inactive workspace
  controllers and unused diagram assets while preserving needed offline content.
- Explicit website preflight measures prepared outputs and reports missing media
  attribution/inclusion; it does not certify rights or mobile performance.
- Unicode counting/evidence mapping, numerical edge cases, text report output and
  several language cue profiles receive the corrections listed in the changelog.

## Single-commit manuscript link reconciliation

Reconciling changed manuscript quotations in `reconcile-manuscript` parses manuscript
paragraphs once and commits all accepted updates in a single transaction:

```bash
lixity research reconcile-manuscript draft.md --accept-moved --accept-claim-updates
```

Batch revision transactions via `revise-batch` also support source-verified
`manuscript_claim_link` anchor updates and `decision_acknowledgement` operations,
allowing complex editorial workflows to commit in one atomic archive revision.

## Multi-file dossier draft reconciliation

External Markdown draft editing (`lixity-dossier-edit/1`) now supports preparing
multiple files in one call:

```bash
lixity research dossier --prepare --edit-file draft1.md draft2.md \
  --change-kind correction --reason "Reviewed chapter notes" --output batch.json
lixity research revise-batch --file batch.json --apply --expected-snapshot <DIGEST>
```

The preparation validates unique dossier IDs within the project, verifies project
identity, reports per-file diffs and conflicts, and generates an atomic
`research-revision-batch-local/1` packet when all drafts are ready.

## Guided pin review and batch preparation

When authors revise dossiers or claims, linked decisions show stale pin candidates.
The new guided review batch preparation translates explicit review choices
(`retarget_dossier`, `retarget_claim`, `acknowledge`, and `keep_pin`) into
a single atomic batch packet:

```bash
lixity research review --prepare-batch actions.json --output pin-review.json
lixity research revise-batch --file pin-review.json --apply --expected-snapshot <DIGEST>
```

Multiple retargeting actions against the same decision are safely consolidated
into one operation, preventing commit conflicts.

## Read-only dossier manuscript evidence projection

Authored dossiers can now inspect their associated manuscript evidence without
modifying the dossier body or creating archive revisions:

```bash
lixity research dossier <DOSSIER_ID> --manuscript draft.md --format json
```

The returned `manuscript_evidence` projection derives:
- Active manuscript quote links for claims pointing to this dossier, with current
  chapter location, line span, and resolution status.
- Configured terms linked to this dossier (`term.dossier_id`), with exact
  occurrences and chapter presence in the manuscript.

## Named dossier collections and reading order

Research archives now support named dossier collections in `lixity.toml`:

```toml
[dossier_collections.historical_figures]
name = "Historical Figures"
dossiers = [
  "urn:uuid:11111111-1111-4000-8000-000000000001",
  "urn:uuid:22222222-2222-4000-8000-000000000002",
]
```

Collections establish explicit reading orders without revising dossier records
or invalidating revision pins. The CLI provides `--collection`, `--set-collection`,
and `--delete-collection` controls.

## Configured manuscript terms and props

Authors can declare terms, props, aliases, and chapter-scoped alternatives in `lixity.toml`:

```toml
[terms.Kaffee]
aliases = ["coffee", "espresso"]
dossier_id = "urn:uuid:11111111-1111-4000-8000-000000000001"

[terms.Carriage.scoped_alternatives]
term = "coach"
chapters = [1, 2, 3]
```

Review candidate occurrences with `lixity research terms draft.md`. Hits outside
declared chapter scopes and overlapping terms are explicitly flagged for human review.

## Capacity and storage upgrades

- Compressed manifest storage reduces archive footprint while keeping canonical
  record hashes, HEAD, and verified source bytes identical.
- Manifest capacity limit increased to 100,000 entries.
- Media attachments support PDF, MP4, and WebM up to 50 MiB with bounded container
  validation and read-only provenance context.

## Upgrade and compatibility

Upgrade the package, verify `lixity doctor`, restart the managed app and reopen
project views from its home address. Installing packages or updating Pages alone
does not restart the local app. Keep model/worker environments explicit and
preserve their separately installed weights. See the
[update guide](https://mfahsold.github.io/lixity/INSTALLATION.md).

Existing research storage can require the explicit verified-backup compression
migration described in the [contributor migration guidance](https://github.com/mfahsold/lixity/blob/v0.7.6/CONTRIBUTING.md#release-migrations-and-the-current-product-path).
Do not delete revisions or retained sources to complete an upgrade. Canonical
hashes, HEAD and source bytes are preserved by that migration. Retained PDF/video
attachments opt into archive/manifest v9; older readers reject those archives.
Portable backup transport remains the restoration boundary.

Grammatical tense is opt-in and adds `grammatical-tense/1` observations. Default
pattern counting and custom regex contracts remain available; do not compare
counts from different policies as unchanged measurements. No manuscript edits,
research claims or publication decisions are inferred from diagnostic signals.
