# Lixity v0.4.1

Released 14 October 2026. A patch release that fixes a layout regression from
v0.4.0 and completes the use-ordered project page.

## Fixes

- **The three workspace views keep their contents apart again.** v0.4.0
  contained a stray closing tag in the project page that closed the project
  pane early, so its controls appeared in every view. The project pane now
  closes where it should, verified by a parser-based pane-ownership test and
  the layout browser suite.
- The project browser badge no longer sits inside the entry button, which had
  broken exact-text selection of project entries.

## Improvements

- Project & Settings follows use order: project data (with the manuscript
  comparison collapsed), **Results** (run analysis plus the generated-file
  list, renamed from "publications" to stop clashing with "Book and
  publication"), the collapsed publication fields and thresholds, and the
  confidentiality agreement last.
- The settings page explains itself: a page introduction, a title hint,
  default values on every threshold ("Default: 2.5"), a default marker on the
  flag severity option, and the FDR method as a real dropdown
  (Benjamini-Hochberg / Benjamini-Yekutieli).
- Research record lists render as a terminal table:
  `lixity research dossier list --format table` (ID, title, revision, date);
  `sources` accepts the explicit `list` verb like the other record commands.
- The untrusted-host response names the loopback URL to open, which removes
  the "Direct IP access" confusion in containers and headless setups.
- Structure guard: rendered dashboards are checked for balanced tags and
  pane ownership in `tests/test_ui_contract.py`.

## Compatibility

- Product version 0.4.1; JSON schemas and research storage are unchanged.
- Upgrade from 0.4.0 with the release wheel
  `lixity-0.4.1-py3-none-any.whl`.
