# Lixity 2.2.0 — One project author for Settings and NDA exports

Open **Project → Settings → Author name** in the loaded project. Apply saves that name in
the project's `lixity.toml`, so it survives a restart and appears beside the
project representative's signature in NDA downloads. Recipient name, optional
address, project, date and place remain the five NDA fields. Lixity has no personal
author default or recipient registry. Author identity is never inherited from
user settings or a parent folder.

The nearby identity check compares the displayed project title and configured
author with explicit manuscript metadata. It recognizes flat leading YAML string
fields `title` and `author`, or a leading Markdown title page with `by`, `von`,
`Author:` or `Autor:`. Missing, unsupported and differing values are reported
separately. This compares written metadata; it does not establish authorship,
scan narrative references for names or change the manuscript.

Only the author field is newly persisted. Title overrides, language and analysis
thresholds retain their current session behavior. Author saving needs an active
manuscript/archive project; no-project sessions cannot write a personal name to
the server's working folder. Invalid types, controls or names longer than 500
characters are rejected. Empty clears the configured name.

The writer preserves unrelated parsed TOML and uses verified, atomic replacement.
Malformed, unsupported or changed config files fail without overwrite; its final
file check is optimistic protection, not a lock on external editors. Invalid
author metadata does not affect linguistic measurements.

Project-owned NDA models may additionally use literal `{{project_author}}`.
Existing five-field models still work. Without a configured name, the default
agreement retains a blank representative-name line for manual completion.
Routes, document formats and analysis JSON contracts are unchanged.

Workspace tabs and dialog controls now use the shared UI font. Settings and
research panels share text-size, weight and line-height roles; technical IDs
retain a consistent monospace font. The existing layout and offline font stacks
are preserved.

Metadata-only PDF refresh reports verification of retained extraction when it
reuses text, rather than announcing OCR that was skipped. Resumable imports,
debug overrides and UTC error timestamps remain available in their existing
interfaces; no additional background service or workflow is required.
