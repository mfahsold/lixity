# Lixity 1.18.0 — honest consistency indicators, localized OCR guidance, source origin URLs, and practical web guides

Lixity 1.18.0 introduces neutral indicators for unmeasured manuscript consistency,
localized OCR diagnostics across all seven interface languages, source origin URL
metadata tracking, practical HTML documentation guides, and a hardened public
documentation staging boundary. The package remains source-available under LNCL-1.0
for non-commercial use.

## Highlights

### 1. Honest Consistency and Empty-Manuscript Handling
- Style consistency now evaluates to `None` and displays as an em-dash (`–`) in the
  dashboard tile, summary cards, and text reports when an empty manuscript or insufficient
  chapter/feature data prevents measurement. It no longer manufactures a misleading `1.0`
  rating on unmeasured texts.
- The style JSON contract adds `measured_cells` (integer count of supporting matrix cells)
  while retaining `consistency=1.0` as a legacy numeric sentinel for backwards compatibility.
- Readability metrics (Flesch, LIX) evaluate to `0.0` rather than formula intercepts on
  zero-length manuscripts.

### 2. Localized OCR Guidance and Upstream Integration Assessment
- In-browser OCR setup diagnostics, worker configuration states, and troubleshooting
  guidance are now localized across all seven workspace languages (English, German,
  French, Spanish, Italian, Dutch, and Polish).
- Configured workers are accurately reported as configured executables, not as certified
  or running inference services.
- Detailed upstream Unlimited-OCR assessment (`docs/research/OCR_INTEGRATION.md`) compares
  official Baidu Transformers, vLLM, and SGLang routes, documents verified pins
  (`07dea832e22aefee32ad281d4b80551282e1c168` and `d49ff64afffc1f47ab563dc1c589bc2f78808fa4`),
  and outlines custom adapter requirements for Lixity's JSON `blocks` protocol.

### 3. Source Origin URL Provenance
- Source ingestion in the web panel, CLI (`--origin-url`), and Python/HTTP APIs now accepts
  an optional HTTP/S source URL.
- Origin URLs are preserved strictly as inert metadata in source records; Lixity never fetches,
  downloads, or uploads remote URLs.
- URL-bearing captures upgrade the archive record to `research-local/2` and require v2
  manifests, ensuring older versions fail explicitly rather than silently dropping provenance.
  URL-free captures continue to use standard v1 records.
- Historical citations and re-index operations maintain exact reference integrity.

### 4. Practical Web Guides and Discoverability
- Three standalone, responsive HTML guides are published with zero-JS fallback, desktop/mobile
  views, and light/dark theme support:
  - **Installation & Setup** (`guides/installation.html`): CLI/server startup, local project creation,
    and first-dashboard workflow.
  - **Metric Interpretation** (`guides/interpretation.html`): KPI thresholds, style fingerprints,
    and heuristic limits.
  - **Research & PDF Ingestion** (`guides/research-pdf.html`): Dual-blob archiving, native text layers,
    origin URL tracking, and worker protocol limits.
- Public site navigation, canonical meta tags, sitemap, and `docs/llms.txt` are aligned.

### 5. Portability and Staged Publication
- CI pipelines install native Poppler dependencies on Linux and macOS; platform tests report
  explicit skips when optional PDF tools are unavailable.
- Staged GitHub Pages builder (`scripts/stage_pages.py`) enforces an explicit allowlist,
  guaranteeing that local agent planning (`.planning/`) and private artifacts never leak into
  public documentation.

## Compatibility and Upgrade Notes

- **Archive format**: Existing archives continue to read cleanly under `research-manifest-local/1`.
  Only new captures specifying an origin URL write `research-local/2` records and manifest v2.
- **Python compatibility**: Supports Python 3.10 through 3.13.
- **Upstream OCR worker**: Baidu's upstream `infer.py` is not a drop-in worker; a small custom
  adapter translating to Lixity's `blocks` protocol is required.
