# Lixity 1.19.0 — Zotero sources, unified research search and stricter OCR capture

Lixity 1.19.0 connects the experimental research workspace to Zotero Desktop's
local API. Zotero manages bibliographic metadata and original media; Lixity keeps
selected immutable evidence, citations, dossiers, claims and author decisions.
Core manuscript analysis remains usable without Zotero or an OCR model.

## Sources and media

- Browse an explicitly selected Zotero library or collection, inspect attachments
  and capture locally available PDF/text files with explicit retention permission.
- Open originals in Zotero and explicitly refresh linked captures. Changed Zotero
  files never silently replace earlier quotations. Images, audio and video can
  remain in Zotero; automatic transcription is not included.
- Export an additive RIS migration bundle with original files and identity tags.
  Bind existing captures only when their original bytes match.
- Back up the research archive together with an explicitly closed Zotero data
  directory. Restore into a new destination after inventory and checksum checks.
  Manuscripts, Zotero application profiles and external linked files require
  separate backup. The command relies on the caller actually closing Zotero.

## Search and capture reliability

- Search current dossiers, claims and decisions alongside retained source
  passages. Authored hits open the existing revision viewer; they are not source
  citations. Historical authored revisions are not indexed.
- Preserve source criticism during migration, prevent duplicate attachment
  identities across personal-library aliases and check concurrent archive changes.
- Reuse verified extraction for metadata-only PDF refreshes with identical bytes.
- Configured OCR workers fail explicitly on errors or incomplete page coverage.
  Physical page order is preserved and missing confidence remains unknown.
  `LIXITY_OCR_TIMEOUT` accepts 1–3600 seconds; the default is 120 seconds.
- An optional experimental CPU adapter is provided in the source checkout at
  `scripts/ocr_unlimited_cpu_worker.py`. It requires a separately prepared runtime
  and model weights, and rejects truncation and unhandled model control tokens.
  It is not a bundled model or a guarantee of recognition accuracy.

## Installation and compatibility

```sh
uv tool install --python 3.12 "git+https://github.com/mfahsold/lixity.git@v1.19.0"
lixity --version
lixity serve ./my-novel --research-project ./my-novel --port 8765 --open
```

Stop an existing Lixity server before restarting with the new installation.
Start Zotero separately with its local API enabled when using the bridge. No
cloud account, automatic synchronization or login autostart is configured.

- Structured Zotero references write `research-local/3` captures and v3 manifests.
  v1/v2 archives remain readable. Older Lixity readers reject v3 archives: back up
  before the first Zotero capture and upgrade all writers of the same archive.
- Default source-only CLI/API search retains its v1 response. Additional scopes
  return typed `research-search-local/2` results.
- The Python package supports Python 3.10+; the optional CPU OCR runtime has
  separate prerequisites. Zotero, Poppler and model weights are not dependencies
  installed by the core package.
- `serve --debug` and `LIXITY_DEBUG` provide server diagnostics; browser diagnostics
  can be controlled with `setLixityDebug()`.
