# Lixity v0.8.0 — draft

**Unreleased draft.** Version 0.8.0 has not been published. These notes describe
changes currently on the development branch and must be reviewed against the
final release candidate. The current published release is v0.7.7.

## Listening and speech direction

Speech plans can be exported as JSON or SSML for a passage, a chapter or the
manuscript without contacting a speech service. JSON retains the planned text,
pronunciation substitutions, delivery direction, voice choices and pauses.
SSML is a projection: inspect its warnings for controls a portable SSML document
cannot express, and check compatibility with the destination engine.

An explicitly configured OpenAI-compatible HTTP provider can render with a
chosen endpoint, model and voice. Credentials remain in an environment variable,
not the saved profile. The provider receives the text selected for rendering;
review its privacy policy and service terms before use. Coqui Thorsten and
optional OpenVoice reference conversion are experimental local alternatives.
Supported controls differ among engines; free-text direction is not universally
available, and a generated voice is not a guarantee of consistent performance.

Local audio inspection reports signal observations. Comparing a recording with a
speech plan also requires a separately produced timed transcript bound to the
recording's hash; Lixity does not transcribe the recording. Missing evidence is
reported as unknown. Audio and reference-quality observations are heuristics,
not an assessment of artistic quality.

## Analysis and reading

The analysis overview and style space provide clearer links, legends, tooltips
and chapter selection. The reported share of comparisons within a threshold is
not a measure of literary quality. Tense and style patterns remain prompts for
reading in context, not confirmed writing errors. Static reports retain usable
chapter links when JavaScript is unavailable.

Style-dimension cards show each raw axis threshold relative to that axis's sample
standard deviation, without changing the existing scores or classifications.
For the default Spanish tense patterns, an adjacent detected present `haber` and
regular participle no longer also counts its auxiliary as a separate present cue;
this remains a lexical heuristic. Existing Spanish review decisions using those
defaults require review under the changed analysis context.
Quotation spans recognized across paragraph boundaries now contribute to each
overlapping paragraph's quotation share. Configured quotation patterns with
multiple capture groups use the first group consistently across analysis;
detection itself remains heuristic.

Research source import preserves an edited draft during asynchronous work and
rejects ambiguous simultaneous file and pasted-text input. Project creation
asks for an explicit language when the existing choice cannot be preserved;
import counts are estimates. Demo reports and guidance reflect the current UI.
The project-creation API rejects invalid or automatic language choices before
writing rather than silently selecting English; integrations must send a concrete
supported language when the current session uses automatic detection.

## Project compatibility and recovery

Valid settings for currently supported engines remain readable in their original
audio schemas. Project-wide pronunciations use schema `/2`, Coqui profiles use
`/3`, and saved external provider profiles use `/4`. Lixity v0.7.7 cannot read
those newer settings.
Before saving an external provider to an existing project, use the explicit
`audio-migrate --to-schema-4` preview and apply with the reviewed snapshot and a
new backup outside the project. The same procedure is available in voice
profiles. Keep separate backups of manuscripts, voice references and research;
the audio migration ZIP contains root configuration files, not those assets.

When testing recovery on a project copy, preserve the current configuration and
restore files listed in the ZIP's `manifest.json`. If the manifest does not list
`lixity.toml`, it did not exist before migration; after preserving any later
changes, remove the migration-created file from the recovery copy so that it no
longer overrides `pyproject.toml`. Verify the recovered project with a compatible
application version. Restored Piper settings require an older version that can
render them; the Qwen replacement is not an equivalent voice.

See the [usage guide](https://github.com/mfahsold/lixity/blob/main/docs/USAGE.md)
for exact migration, audio export and recovery instructions, and the
[stability guide](https://github.com/mfahsold/lixity/blob/main/docs/STABILITY.md)
for measurement limitations.
