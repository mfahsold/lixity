# Lixity v0.6.0

Released 19 October 2026. Installed configuration becomes inspectable, CLI help
uses the backend's threshold rules, and Settings can explicitly save analysis
choices as project defaults. Shorter documentation points to these interfaces
while preserving scientific, storage and concurrency contracts.

## Inspect installed capabilities

```sh
lixity schema --section configuration
lixity about --section features
lixity style --help
```

`about` and `schema` select languages, features, heuristics, commands or
configuration. Each selected response retains version metadata. The additive
`configuration` object uses `lixity-configuration/1` and describes accepted keys,
component schemas, defaults and settings scope without reading project values.
Metadata and shell completion remain available beside malformed configuration.

Corpus, threshold and publication descriptions reuse their existing models and
validation policies. Defaults are annotations, not the effective settings of a
project or server. Component validators still enforce rules that JSON Schema
does not fully encode, including register assignments, threshold relationships
and publication year/ISBN checks. This is not a complete project-file or
analysis-result schema.

CLI threshold help now states finite-number requirements, bounds and defaults
from the shared backend rules. Invalid scalar arguments return usage error 2 before reading
configuration or manuscripts.

## Save analysis defaults deliberately

Settings explains session and project scope beside its controls in all seven
interface languages. **Save analysis defaults for this project** is unchecked
by default. Ordinary Apply keeps language and detection thresholds in the
server session; selecting the option saves the posted analysis fields in the
selected project's `lixity.toml`.

Saving requires the current project token, validates the resulting project
thresholds, and reuses the existing atomic settings transaction. Stale project
or root-configuration changes are rejected. Failed preparation, rendering or
writing preserves the prior settings. Literal `auto` and exact numeric values
are retained; unposted defaults and manuscript bytes are unchanged.

## Documentation and examples

The README and Pages explain chapter comparisons separately from paragraph
measurements. New worked articles cover
[intentional chapter registers](https://mfahsold.github.io/lixity/blog/intentional-registers.html) and
[local phrase echoes](https://mfahsold.github.io/lixity/blog/local-word-echoes.html), using synthetic examples
checked against the implementation.

Onboarding, architecture and automation references are consolidated. Generated
Markdown alternatives and the full documentation bundle remain aligned. The
Pages browser check discovers staged HTML pages automatically and waits for
actual fragment navigation when JavaScript is disabled.

## Compatibility and verification

Analysis/profile JSON remains schema 2, style JSON remains schema 4, and
research archive support remains versions 1–7. This release introduces no
archive migration. Existing settings requests retain their default behavior;
analysis-default persistence requires the new explicit opt-in.

Validation covers configuration discovery, CLI errors before processing,
project/configuration conflicts, atomic-write rollback, exact values and
seven-language desktop/mobile settings. Native browser flows save defaults,
reopen the project and check that manuscript bytes remain unchanged.

After installing the update, restart the intended local service to load it.
Publishing the package or Pages does not restart an existing local instance.

[usage](https://github.com/mfahsold/lixity/blob/v0.6.0/docs/USAGE.md), and the
