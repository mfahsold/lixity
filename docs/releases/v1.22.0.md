# Lixity 1.22.0 — Server decomposition, lifecycle tooling, and verified issue closure

Lixity 1.22.0 is a maintenance and architecture release. It removes roughly 350
lines of unreachable code, splits the 1655-line `server.py` into a focused
package, fixes two real defects found while verifying issues #10, #11 and #12,
and ships cross-platform server lifecycle tooling for Windows, macOS and Linux.

## Breaking and compatibility changes

- **`research claim_matrix(project, format=...)` is deprecated.** The
  `format=` argument now emits a `DeprecationWarning` and will be removed in
  **v1.23.0**. Use `claim_matrix_data(project)` for the dictionary and
  `render_claim_matrix(data, format=...)` for Markdown or CSV, or
  `claim_matrix_format(project, format=...)` for both in one call. The JSON
  contract is unchanged, and `lixity research matrix` output is byte-identical
  for all three formats.
- **Vargha–Delaney A is no longer documented as reported.** `METHODS.md`,
  `STABILITY.md` and `llms.txt` described an implied Vargha–Delaney value on
  FDR-confirmed cells. No payload ever carried it — the code only emitted
  Cliff's δ labels. The documentation now describes what is actually emitted,
  and the unused `vargha_delaney_a()` helper is removed. Consumers wanting
  Â derive it as (δ + 1) / 2.

## Architecture

- **`lixity.server` is now a package.** The single 1655-line module became eleven
  focused modules: `runtime` (bind checks and startup), `views` (dashboard
  rendering, HTTP-independent), `_state` (workspace state and the single
  `refresh()` writer), `_base` (response helpers plus Host/Origin guards),
  `routes_project`, `routes_research`, `routes_nda`, `routes_markers`, `handler`
  (route tables and dispatch), `constants` and `__init__`. The public surface
  (`run_server`, `LixityServerHandler`, `build_server_dashboard`,
  `sanitize_filename`, `collect_artifacts`) is unchanged, so
  `from lixity.server import …` keeps working.
- **Routing is declarative.** The 73-line `do_GET` and 125-line `do_POST`
  if-ladders became `GET_ROUTES` / `POST_ROUTES` tables plus focused
  request-validation helpers. Each route group is a plain class that can be read
  and type-checked independently.
- **Data and rendering are separated in the research API.**
  `compare_source_to_manuscript()` now returns only the comparison dictionary —
  the `format` parameter and two `@overload` stubs are gone, and
  `format_compare_markdown()` is the renderer. `claim_matrix_data()` returns
  matrix data; `render_claim_matrix()` renders it. Callers no longer branch on a
  `dict | str` union at six call sites.
- **Removed unreachable code**: `layout.py` (237 lines of book-layout geometry
  with no references outside its own test, not exported from the package) and
  `inline_markdown_to_html()` (an EPUB renderer that nothing consumed).

## Fixes

- **NDA PDF receipts were unreadable.** The generator wrote a hand-built
  cross-reference table with hardcoded offsets and a hardcoded `startxref 350`.
  The offsets were wrong for every input and shifted with each recipient ID, and
  the page declared no font resource — `pdftotext` reported `Unknown font tag
  'F1'` and extracted no text at all. Offsets are now computed from the assembled
  bytes, the font is declared, and string content is escaped. A regression test
  asserts a self-consistent cross-reference table and a declared font; it fails
  against the previous generator.
- **`lixity serve` reports an occupied port usefully.** The port is probed before
  any setup work, so a conflict aborts with the conflicting port and the
  commands to open, relocate or stop the existing instance instead of a bare
  `OSError: [Errno 98] Address already in use`. Covered by a regression test.
- **Strict search blamed the wrong thing.** With no index file,
  `research search --strict` failed with "Search index unavailable … with an
  FTS5-enabled SQLite" even when FTS5 was present and working. It now reports
  "Search index not built; run research reindex".

## Server lifecycle

Cross-platform launcher scripts, all documented in `INSTALLATION.md`:

- `scripts/lixity-start.sh` (Linux/macOS) and `scripts/lixity-start.ps1`
  (Windows PowerShell 5.1 and 7+) provide `start`, `status`, `restart` and
  `stop` with a PID file. Both verify that a recorded PID is still a Lixity
  process before acting on it, so a recycled PID is not mistaken for a running
  server. The shell launcher rotates its log on every start, so a failed start is
  reported as a failure rather than matching a readiness line left by a previous
  run. `make serve` and `make stop` wrap the shell launcher.
- `scripts/lixity.service` (systemd user unit), `scripts/lixity.plist` (launchd
  agent) and a documented Task Scheduler registration provide auto-start at
  login. The unit deliberately omits `ProtectSystem=`/`ProtectHome=`: the server
  writes `exports/` and the research archive inside the manuscript project
  directory, so a read-only filesystem would break it for any project outside
  the home directory.

## Documentation

- `AGENT_PROFILE.md` states the agent operating rules — verify before asserting,
  never let a formatter rewrite unrelated code, check an issue's premise against
  the base, data boundaries and escalation. It is delegated to from `AGENTS.md`
  and published to Pages.
- `docs/AGENTS.md` §5.2 now documents the six NDA HTTP actions, their payload
  fields and the 404 capability contract. They were implemented but undocumented.
- `ARCHITECTURE.md` describes the new server package and its layering.
- `docs/research/USAGE.md` is retitled from "pilot" to "archive" and its
  capability table now states v1.21.0.

## Verification

Issues #10, #11 and #12 were checked as executable assertions mapped one-to-one
onto the claims in their bodies: **30 of 30 pass**. Three checks failed on the
first run and all three were the checks being wrong rather than the product; the
results are posted to each issue. Two durable regressions were promoted to unit
tests (NDA PDF validity, and the existing strict/non-strict search contract).
The server split was additionally verified against a live instance across 21
routes and request-guard conditions.

Full suite: 553 tests, 2764 subtests, under `-W error`. `ruff` clean, `mypy
--strict` clean across 58 files.
