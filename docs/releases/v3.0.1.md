# Lixity 3.0.1 — Chapter thresholds in server startup

This patch fixes startup with an explicit `--min-chapters` value. The service
controller already accepted and saved the option, but the foreground `serve`
parser rejected it when the managed worker started. Since v3.0.1, foreground
servers and managed start/restart accept the same chapter threshold.

For example, with the managed instance stopped:

```sh
lixity service start --min-chapters 4 ./my-novel
lixity service restart
```

Replace the project path with your own folder. Restart retains the saved
threshold unless you override it. Values must be integers of at least 2;
fewer usable chapters leave style baselines unavailable.

The claim-list API change and research features introduced in 3.0.0 remain.
This patch changes no JSON or archive format. Existing v1–v5 archives remain
readable without conversion; only an explicit causal-link write opts an archive
into v6. Manuscript and retained source bytes are unchanged.

Stop managed instances before replacing the installation, verify the installed
version, then start or restart the intended instance. See the
[service command reference](https://github.com/mfahsold/lixity/blob/v3.0.1/docs/USAGE.md#lixity-service),
[update instructions](https://github.com/mfahsold/lixity/blob/v3.0.1/docs/INSTALLATION.md#updates-and-removal)
and [3.0.0 feature and compatibility notes](https://github.com/mfahsold/lixity/blob/v3.0.0/docs/releases/v3.0.0.md).
