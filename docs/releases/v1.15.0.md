# Lixity 1.15.0 — coherent dashboards, explicit configuration and safer rendering

This release consolidates the analysis pipeline, improves manuscript inspection
on desktop and mobile, and fixes security issues in optional adapter controls.
It remains source-available under LNCL-1.0 for non-commercial use.

## Highlights

- Shared `lixity.pipeline` computes corpus metrics once and reuses them for
  paragraph profiles and the style fingerprint. Projects reuse the engine
  rather than maintaining analysis copies.
- A consistent panel-spacing system, readable mobile tables/charts, clearer
  settings and project/version identity. The book-style serif is limited to
  the project title; interface text retains a system sans-serif.
- Interactive 3D style dimensions with accurate point picking, zoom and
  rotation controls. Rendering is idle when no animation is requested.
- Clearer style-reference and fingerprint displays: fixed color-scale legend,
  FDR markers/filtering, sample counts, robust-reference explanations and
  chapter-matrix tooltips in seven languages, including keyboard support.
- English analysis defaults and explicit automatic detection, with localized
  linguistic resources, numerical formatting and scientific explanations.
- `--min-chapters` on `style`, `dashboard` and `build`; matching API calibration
  arguments and explicit threshold mappings for project isolation.
- Isolated installation recipes, Windows/API/update guidance, refreshed public
  screenshots, neutral agent guidance and documented integration boundaries.

## Security fixes

NDA records returned by an adapter are now rendered using DOM text properties,
not raw HTML interpolation. Artifact links reject executable URL schemes.
Update the engine, restart the embedding server and reload open dashboards.
Previously exported HTML embeds its old scripts; regenerate it to receive fixes.

These fixes do not make arbitrary adapters safe for remote exposure. Keep local
services on loopback and treat generated dashboards as private manuscript data.

## Migration checklist

1. **Choose the manuscript language.** Defaults are now English. Pass
   `--language de` for German or `--language auto` for detection. Existing
   pipelines relying on implicit detection must select it explicitly.
2. **Use Python 3.11+ for TOML settings** (3.12 is the installation default).
   Python 3.10 still runs the engine, but does not load project TOML settings.
3. **Review project isolation.** Explicit CLI file paths load configuration
   relative to that manuscript. API `project_config={}` disables implicit
   threshold discovery; language/title/corpus options remain explicit.
4. **Review thresholds.** `min_chapters` is now honored by the public API and
   must be an integer of at least 2. Re-read resolved settings from passport
   metadata; threshold hits and FDR-selected cells are different result sets.
5. **Use the local environment.** `make install` now creates `.venv` instead
   of installing into global Python. Invoke `.venv/bin/lixity` or activate it.
6. **Use one NDA workflow.** The duplicate legacy entry form was removed;
   the encrypted NDA manager remains available through supporting adapters.

JSON analysis/profile schema remains v2; the style passport remains v4.
No manuscript migration or destructive data conversion is performed.
Standalone HTML is an analysis document, not a bundled editing/NDA server.

## Install or replace an older CLI

Requires Git and uv:

```sh
uv tool install --force --python 3.12 "git+https://github.com/mfahsold/lixity.git@v1.15.0"
lixity --version
lixity build manuscript.md --language en
```

Open `exports/manuscript_dashboard.html`. The tag is pinned; selecting a future
release requires changing the tag explicitly. Wheel and source distribution
downloads include `SHA256SUMS` for integrity verification. This checksum file
is not a cryptographic signature or independent publisher attestation.

## Validation and limits

Release preparation includes Python tests, strict typing/lint, browser layout
and interaction checks at 320/390/768/1440 pixels, synthetic injection tests,
clean-environment installation and idempotent workspace builds. CI covers
Python 3.10–3.13. These checks do not establish language-wide accuracy or an
objective writing-quality measure. Small corpora and heuristic patterns still
require careful interpretation; canvas keyboard navigation remains limited.
