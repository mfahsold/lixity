# Lixity v0.7.1

Released 19 October 2026. This release makes research editing easier to inspect,
keeps Zotero at the centre of source-library work, and improves local maps,
images and diagrams. It includes all product changes since v0.7.0.

## Research without a parallel editing system

Research opens with dossiers, claims and manuscript review. Zotero remains the
interface for bibliography, reading and source notes; Lixity retains selected
evidence and authored records. Local capture remains available without Zotero.

An existing dossier can be exported to Markdown, edited externally, compared
with its saved revision and returned through an explicit three-way preview.
Reviewed batch packets bind the project and archive snapshot; intervening writes
require a new review. There is no background synchronization or automatic claim
acceptance. Exact update dry runs and saved-revision diffs use the same revision
validation as actual writes.
Manuscript reconciliation keeps explicit acceptance: combined anchor/claim
changes create one revision per association, while a multi-association run may
skip unresolved quotes or partially succeed. Review its results afterward.

Research help groups related commands; empty drafts name the record's editable
inputs. Plural aliases and bare UUIDv4 selectors
are accepted at the CLI; stored identifiers and API contracts remain canonical.
Positional IDs, `show`, `inspect` and named dossier reads consistently honor
section, summary, citation and historical-revision bounds.

**Migration:** dossier `--file` now means an existing readable UTF-8 file.
Use `--body` for literal text. A missing path is an error; it is no longer saved
as dossier content. Existing scripts relying on that fallback must change.

The existing withdrawal command can retire a dossier with explicit snapshot and
revision guards and a read-only preview. Active lists and search omit retired
dossiers, while exact historical records and existing associations remain
available. This does not merge dossiers or infer replacements.

## Maps, retained images and diagrams

Bundled **Leaflet 1.9.4** adds pan, zoom, selection and fit to existing dossier
geography. Vectors work offline. Optional OpenStreetMap tiles require explicit,
nonpersistent permission and disclose the viewed area and client IP to the
provider. There is no geocoding, road routing, travel-time calculation or
automatic sightline verification.
Dossier Markdown formatting also preserves underscores in link destinations,
preventing stray emphasis and duplicate map fallback views.

Retained images and diagrams share a **PhotoSwipe 5.4.4** zoom viewer with
keyboard navigation, captions and focus restoration. Galleries include lazy
images and adjust their dimensions after loading.

Bundled **Mermaid tiny 12.2.0** renders supported diagrams locally. Source stays
inspectable; unsupported or restricted syntax remains readable as source.
External resources, custom configuration and interactive diagram actions are
restricted. These viewers require no CDN or diagram upload.

Try the [read-only research example](https://mfahsold.github.io/lixity/demo/research.html).
Its historical map and harbour print have source credits; people, events and
journeys are explicitly fictional demonstration data.

## Character profiles and clearer counting

Project-local character profiles provide literal aliases and optional
author-declared viewpoint chapters. Declared perspective stays separate from
name counts; Lixity does not infer pronoun identity, speakers or physical presence.
Explicit name selections retain their existing matching semantics.

Shared counting excludes Markdown destinations, images, code and comments while
preserving displayed paragraph anchors and chapter numbering. Regenerate saved
reports and comparison baselines when manuscripts contain these constructs;
response schema numbers are unchanged. Writer diagnostics
distinguish lock contention from read-only, permission and other I/O failures;
the canonical OS lock and its location remain unchanged.

## Documentation and compatibility

Historical v3.x releases have higher version numbers than this pre-1.0 line.
Ordinary package upgrade ordering will not select v0.7.1 from them; explicitly
install the [pinned release wheel](https://mfahsold.github.io/lixity/INSTALLATION.md#cli-current-release)
or select v0.7.1 and reinstall. Back up project archives before switching versions.

The README, research entrypoints and status references are shorter and defer exact
options to installed help and runtime discovery. Historical design and completed
implementation notes remain accessible through fixed Git links. Proposals stay
separate from shipped interfaces.
Pages now share clear site and parent links, reading paths and a keyboard-friendly
return to the top, including without JavaScript. Public examples embed the same
navigation styles and remain standalone reports.

Research remains experimental. Product versions, response schemas and archive
versions are independent. v0.7.1 reads record/manifest versions v1–v8, including
v0.7.0 geography. Ordinary dossier encodings remain unchanged; these workflows
do not introduce an archive migration. Integrity checks do not verify facts or
literary quality. See the [research reference](https://mfahsold.github.io/lixity/research/USAGE.md)
for data boundaries and compatibility limits.
