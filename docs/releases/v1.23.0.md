# Lixity 1.23.0 — Clearer workflows and contextual diagnostics

Lixity 1.23.0 improves project navigation, manuscript import and research list
filtering. It also corrects dialogue counting and a lexical-diversity boundary,
removes arbitrary Show/Tell rankings, and preserves PDF extraction warnings
through import results. Diagnostic guidance describes statistical and heuristic
limits without prescribing literary targets.

## Workspace and frontend

- **Three workspace views:** Research & Dossiers, Manuscript & Analysis, and
  Project & Settings separate the main workflows. New Project, Open Project and
  optional guidance remain available in every view.
- **Explicit manuscript import:** choosing or dropping one `.md`, `.markdown`
  or `.txt` file shows its filename. In the native server, **Continue to import…**
  opens the existing import dialog; confirmation creates a separate project.
  **Open Project** reconnects an existing archive. Embedding hosts with the load
  capability retain their explicit analysis action and existing load payload.
- **Reliable file controls:** native buttons support click, Enter and Space.
  Import previews clear while reading a replacement; obsolete completions cannot
  overwrite the latest selection. Failed reads cannot be confirmed, and pending
  submissions cannot be duplicated.
- **Local research filters:** source and dossier lists match loaded titles, tags
  and IDs; dossiers additionally match excerpts and section names. Typing sends
  no request, preserves opened details and retains all association options.
  Full-text search remains a separate action.
- **Optional NDA controls:** the capability-gated manager starts collapsed in a
  native details panel. Its backend contract is unchanged.
- **Reusable rendering:** the dashboard uses focused modal, research, narration,
  heatmap and marker modules while retaining existing DOM contracts. Research
  requests consistently use the configured API prefix.

## Verified diagnostic corrections

- **Dialogue ratios use one tokenizer.** Punctuation-only quote chunks previously
  counted as words in the corpus/chapter numerator. A synthetic `"Hi , !"` could
  produce a chapter ratio of 300%. Corpus, chapter, paragraph, dialogue and pacing reports
  now use the configured word regex consistently; that example measures 100%.
  Comma-adjacent words also agree across reports. The legacy whitespace-based
  `clean_words` field remains unchanged.
- **Unavailable Show/Tell comparisons are explicit.** Existing ranking arrays
  are empty when chapter balances cannot be distinguished. The dashboard uses
  dashes and omits comparative bars for fewer than three chapters or absent
  comparative signals. Numeric JSON fields retain their existing zero sentinel
  values; no analysis schema is changed.
- **Maas a² includes one word type.** At `N=100, V=1`, the formula is defined and
  now returns `0.5`. Zero types and texts below the existing 100-token floor
  remain unavailable.
- **Scene estimates disclose their units.** When no scene separators are found,
  the pacing panel explains that scene metrics use chapters as units.

All seven language packs now describe Guiraud as length-sensitive, Flesch as an
unbounded formula output, and long/short sentences as length measures. Style
bands are descriptive. Passives, nominal style and perception words may serve an
intentional register; their lexical detection is not a judgement of literary
quality. Minimum-token guards do not establish confidence or universal sample
adequacy. HD-D retains its exact 42-token hypergeometric estimator and existing
local minimum.

English and German terminal/Markdown reports use the same neutral distinctions:
perception-word matches are lexical signals, and sentence-length categories do
not establish syntactic nesting, complex thoughts or narrative pace. Existing
report-text override keys remain available to project adapters.

## OCR and research reliability

- A successful worker probe no longer overrides an invalid OCR timeout or a
  missing rasterizer. It upgrades the status to `ready (probed)` only when the
  configured prerequisites are satisfied.
- Explicit native fallback after OCR failure carries extraction warnings through
  local ingestion, batch outcomes, Zotero captures and attachment summaries.
  Dashboard import status displays these warnings as text.
- Ingestion adds a `warnings: list[str]` field to its existing result envelope.
  It is empty when no extraction occurs, including unchanged-byte reuse. Warnings
  describe the current extraction attempt and are not stored in source archives.
  Existing envelope versions, identifiers, archive schemas and exit codes remain
  unchanged. Consumers should tolerate this additive result field.

OCR remains an explicitly configured optional executable worker. This release
does not install a daemon, enable fallback automatically or download models.
`ocr-status` retains its diagnostic exit-zero behavior; automation must inspect
`status` and `probe.ok`. Progress reports phase transitions on stderr rather than
periodic heartbeats. Snapshot checks still protect reviewed source identity;
writer-lock contention remains a fail-fast condition.

Research sources remain separate from manuscript style baselines. Source analysis
describes the selected source itself; explicit source/manuscript comparison does
not recalibrate manuscript bands or certify genre suitability, provenance or
historical truth. Methods and workflow guides explain these boundaries and a
scene/voice review workflow using implemented metric fields.

## Compatibility and documentation

- Analysis/profile **v2**, style **v4**, default English analysis and explicit
  research-project settings are preserved.
- The deprecated `research_api.claim_matrix(format=...)` wrapper remains
  available. Its announced removal in v1.23.0 is deferred to a future release.
  Use `claim_matrix_data()`, `render_claim_matrix()` or `claim_matrix_format()`.
- Server launchers retain port-scoped PID/log files and stale-process checks.
- README and GitHub Pages contain 35 refreshed desktop/mobile captures with
  full-size links. Analysis uses the public-domain Austen sample; project and
  research records are synthetic. Dialog captures show complete forms; long
  dialogs scroll in the application.

## Validation scope

Regression tests cover tokenization agreement, unavailable/variable chapter
comparisons, the Maas boundary, invalid OCR configuration and warning propagation.
The complete Python suite runs with warnings treated as errors, alongside Ruff,
strict mypy, documentation/link checks and eight Chromium browser suites.
Rendered desktop and compact mobile states, both gallery lightboxes, and isolated
wheel installation are checked before publication.

Validation uses synthetic or public-domain content. It does not audit a private
manuscript, a production source archive, historical factual accuracy or literary
effectiveness. External OCR and Zotero environments still require their own
configuration and operational checks.
