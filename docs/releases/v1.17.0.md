# Lixity 1.17.0 — native editing, self-hosted OCR, offline diagrams and verified export

Lixity 1.17.0 adds native research record editing with immutable revision history,
self-hosted OCR document extraction, offline vector diagram rendering, and
cryptographically verified archive export and restoration. The package remains
source-available under LNCL-1.0 for non-commercial use.

## Highlights

### 1. Native Revisions and History
- Authorial research records (dossiers, claims, evidence links, and decisions) now support
  native in-place editing in both the web UI and CLI.
- Logical record IDs (`urn:uuid:...`) remain permanent across revisions. Authors specify
  explicit intent (`correction` or `supersession`) along with a mandatory non-blank reason.
- Earlier references remain attached to the exact revisions they originally cited. Changing
  a claim does not silently alter the provenance of prior evidence links.
- Concurrent edits are protected via snapshot and revision conflict detection: saving against
  a modified archive reports a conflict and retains the author's browser draft.
- Interrupted-save recovery safely quarantines valid next-revision files as `.unpublished`
  recovery artifacts before retrying, preserving byte-exact drafts without overwriting accepted history.

### 2. Self-Hosted Baidu Unlimited-OCR Extraction Boundary
- Ingest PDF documents directly via `lixity research ingest --project ./proj --file ./doc.pdf --allow-retention`.
- Content-addressed dual-blob storage: original binary PDF bytes are retained in `blobs/` under
  `application/pdf` (up to 50 MiB), while extracted UTF-8 text is stored separately (`text/plain`).
  Passages map exact character offsets to the text blob.
- Reproducibility pins: official Baidu Unlimited-OCR model snapshot `07dea832e22aefee32ad281d4b80551282e1c168`
  and integration recipe revision `d49ff64afffc1f47ab563dc1c589bc2f78808fa4` (recipe date: 2026-07-29).
- Physical 1:1 page rastering via system `pdftoppm` with per-page SHA-256 digests.
- Sub-process isolation via `LIXITY_OCR_WORKER` JSON protocol, with automatic local fallback to `pdftotext`.

### 3. Safe Markdown and Offline SVG Diagram Rendering
- Dossier bodies support safe Markdown rendering (headings, paragraphs, lists, blockquotes, code blocks,
  and GFM tables). Raw HTML is strictly escaped.
- Inline vector diagram generator: fenced code blocks with `mermaid` syntax convert directly into
  responsive inline SVGs entirely on the client side, with zero external network requests, CDNs, or JS libraries.
- Supported diagram types: flowcharts (`graph TD`, `graph LR`) and sequence diagrams (`sequenceDiagram`).
- Collapsible "Show diagram source" control with localized UI labels across all 7 supported languages.

### 4. Cryptographic Archive Export & Restoration
- Package complete research archives with `lixity research export --project ./proj --output backup.tar.gz`.
- Restore archives into clean directories via `lixity research restore --from backup.tar.gz --to ./restored`.
- BagIt-style verification: includes an explicit `EXPORT_MANIFEST.json` containing SHA-256 digests
  and byte lengths for every file, verified during restoration before atomic move.
- Excludes disposable search indexes (`catalogue.sqlite3`) and lock files; full round-trip audit and citation fidelity verified.

### 5. Correctness & Data Integrity
- **Purge atomicity**: orphan record files and blobs are deleted strictly *after* HEAD has rotated atomically.
- **Evidence reference deduplication**: multiple identical passage IDs in a single dossier call are deduplicated.
- **Hypothesis property tests**: stateful machine verification of content-addressable storage invariants,
  round-trip fidelity, and revision contiguity.
- **Mutmut mutation configuration**: added targeting repository and revision data-integrity paths.

## Compatibility and Upgrade Notes

- **Manifest format upgrade**: The first accepted authored edit upgrades the archive to
  `research-manifest-local/2` and writes `research-local/2` revision records.
- **Read compatibility**: Reading an existing `v1.16.0` archive does not modify or upgrade any files.
- **Writer compatibility**: Lixity 1.16.0 cannot read an upgraded `research-manifest-local/2` archive.
  Ensure all collaborators are updated to 1.17.0 and create a full backup (`lixity research export`)
  before authoring edits.

## Installation

```bash
uv tool install --python 3.12 "git+https://github.com/mfahsold/lixity.git@v1.17.0"

```
