# Lixity 2.1.0 — Visual references and smaller research workflows

Keep a local image beside dossier notes, edit one section at a time and start a
linked claim or decision from the current topic. Review controls, settings and
failed saves now behave more consistently across the interface and backend.

## Local dossier images

Choose **Add image**, preview an authorized PNG/JPEG, describe it and confirm
retention. A caption, source-page link, provenance note and section are optional.
Saving publishes the original image and dossier revision together; a stale or
invalid save accepts neither. Earlier dossier versions keep their exact image
version. Click to enlarge, or use the keyboard and Escape to close.

Images reuse the existing immutable source/archive lifecycle and backups. Missing,
withdrawn and purged references display an unavailable placeholder. They have no
text passages or linguistic scores; Lixity does not download remote pictures,
recognize image text or perform visual AI analysis.

Limits are 16 MiB and 64 million pixels per image, with 32 MiB for image-specific
JSON requests. Other JSON requests retain their 5 MiB limit. Static PNG and supported
8-bit Huffman JPEG containers are checked for structure and dimensions; these are
not full codec validation or factual authenticity checks. The browser decoder can
still reject damaged pixel data. See [the image reference](../research/USAGE.md#keep-a-visual-reference-in-a-dossier).

**Archive compatibility:** source-version purge records now retain their exact
source identity under `research-local/2`. Existing v1 bytes stay unchanged;
2.0.0 rejects new owner-bearing Tombstones. Keep a backup and use compatible
writers after a new release writes an archive. Old associations whose ownership
cannot be established remain missing rather than acquiring another source's reason.

## Work on smaller pieces

**Edit section** opens one unique heading's content in the existing revision
editor. A three-way preview preserves current changes in other sections and asks
you to choose when the same section changed. Reasons, change categories and pinned
evidence remain part of the normal save. **Add claim** and **Add decision** select
the current dossier by title; optional metadata stays available under disclosure.

After your own accepted acknowledgement, matching controls and current review
counts update so the next pair is ready. An external write still requires explicit
refresh; the interface does not silently acknowledge an unseen version. Focus and
unrelated draft text remain where you left them. Marker notes have visible Save,
Cancel, pending state and errors that retain your text.

## One validation policy and fewer steps

The NDA text now reads as a short, direct confidentiality agreement in all seven
languages. Its title omits “draft for review”, the name field identifies the
recipient, and signing guidance stays in the app. Confidentiality, permitted use,
legal exceptions, ownership and handling of copies remain covered. The five fields,
stateless downloads and technical interfaces are unchanged. A downloaded file does
not record the parties' consent or signatures.

Settings use the mathematical core's finite-number and relationship rules without
extra UI ceilings or decimal step rounding. A language-only update preserves
unposted thresholds. HTTP numeric fields require JSON numbers; strings, booleans
and fractional integer values are rejected rather than silently coerced. Estimator
values and analysis/profile/passport schemas are unchanged.
Default metric, profile and passport results were compared with 2.0.0 on the
checked-in *Effi Briest* and *Pride and Prejudice* samples and matched after
excluding version metadata. This is a regression check, not literary calibration.

The native workspace shows one **Update analysis** action. `/api/analyze` and
`/api/rebuild` remain supported, as do distinct actions supplied by embedding hosts.
Selecting a manuscript opens its preview directly; you still confirm creation of
a separate project. Existing projects use **Open Project**. Initial research lists
reuse the overview response instead of immediately fetching them again.

Maintained English guides and synthetic screenshots describe these workflows in
place. Service instructions have one port setting and API examples explain shared
result reuse. Regression cases join the existing Chromium workflow without a new
CI matrix or persistent screenshot artifacts.

The source-only experimental Unlimited-OCR CPU bridge has been removed. Local
Tesseract remains available; it is a different OCR engine, not identical model
output. An existing `LIXITY_OCR_WORKER` pointing to the retired script needs a
project-owned adapter or selection of the built-in backend. The generic worker
contract and previously retained evidence remain unchanged. The old setup recipe
has been reduced to a bounded historical experiment in the existing OCR guide.
