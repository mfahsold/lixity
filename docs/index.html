Lixity

An offline text-linguistics engine that measures how a literary manuscript reads – sentence rhythm, length-invariant lexical diversity, tense continuity, narrative distance, and register signals – and flags only the passages where a chapter departs from its own established voice.

Less Setup, One Analysis Path

Explore, Then Read

Use the 3D chapter view as an entry point, not a verdict. Toggle the trajectory and threshold box, inspect feature directions, then read the underlying passage. Mobile layouts keep the controls and loading labels usable. Rotation runs only when requested and pauses in hidden tabs.

Reuse the Engine

CLI, API and adapters share a typed analysis pipeline. Corpus metrics are computed once per complete analysis and reused for fingerprint assembly. Rendering consumes results rather than recalculating them.

Keep Projects Separate

Pass explicit project settings and thresholds when serving multiple manuscripts. Characters, motifs, publication artifacts and local NDA workflows belong to project adapters, not global engine defaults.

English Default, Language-Aware Analysis

Choose a supported manuscript language or enable --language auto. Profiles supply linguistic patterns, syllable rules and readability coefficients alongside translated labels and scientific help. Language support is more than interface translation.

Target Personas & Workflows

Fiction Authors & Novelists

Macro-editing and pacing diagnostics: detect accidental slips between narrative present and past, balance dialogue with prose, and evaluate rhythm variation (CV) across chapters.

Literary Editors & Translators

Objective chapter consistency inspection without arbitrary external dogmas. Insert persistent, editor-visible work markers (<!-- LIXITY-MARKER ... -->) that vanish in final print and EPUB exports.

Digital Humanities Scholars

Rigorous, reproducible corpus stylometry: length-invariant lexical diversity (HD-D, Yule’s K), Miller-Madow bias-corrected Shannon entropy, and Jacobi eigendecomposition in pure Python.

AI Agent & Pipeline Engineers

Deterministic JSON contracts (schema_version 2 for analyze/profile, 4 for the style reference with structural diagnostics, language-neutral tense values), standardized exit codes, and a stable programmatic facade (lixity.api) designed for autonomous coding and editing agents.

What Lixity Measures

Sentence Rhythm

Average sentence length (ASL), coefficient of variation (CV), and length distribution from staccato (≤ 6 words) to hypotaxis (> 25 words).

Lexical Diversity

Length-robust measures: Guiraud R, hypergeometric HD-D (McCarthy & Jarvis 2010), and Yule’s characteristic K for vocabulary concentration.

Tense Dynamics

Paragraph-by-paragraph detection of narrative present vs. epic past, line anchors, and friction severity flags (0–3).

Register Signals

Dialogue share, function-word ratio, sensory perception filters, modal density, passive markers, and nominal style suffixes.

Self-Calibrating Style Reference

The manuscript’s own house style derived via median/MAD, significance-adjusted deviations z*, and Benjamini-Hochberg FDR control (BH or BY).

Structural Diagnostics

Where the house style shifts (PELT changepoints), whether features drift (Mann–Kendall), robust Sn/Qn scales beside MAD, heavy-tailed features (Hill tail index), early/late Wasserstein–KS distribution shift, content-word co-occurrence (Goh–Barabási fitness), and Dunning keyness between chapter halves.

Style Dimensions

Unsupervised discovery of latent stylistic axes via Spearman rank correlation and cyclic Jacobi eigendecomposition.

Structure Modules

Dialogue turns, character presence, scene/pacing with hook scores, motif tracking, and self-calibrating showing-vs-telling balance per chapter.

Install & create your first dashboard

Use an isolated CLI environment on Windows, macOS or Linux. Install Git and uv first; uv can supply Python 3.12. No account, API key or manuscript upload is needed.

uv tool install --python 3.12 "git+https://github.com/mfahsold/lixity.git@v1.15.0"
lixity --version
lixity about
lixity build manuscript.md --language en

Use a UTF-8 Markdown manuscript with ## Chapter title headings. Open exports/manuscript_dashboard.html locally. For German, use --language de; automatic detection is explicit.

Version choice: @v1.15.0 pins this release. Select a future tag explicitly to upgrade; uv tool upgrade lixity retains the chosen ref. Use @main only for development builds.

Non-commercial use only (LNCL-1.0). Not on PyPI. Python 3.10+ supports the engine; TOML project settings require 3.11+. Standalone HTML is not an editing/NDA server; those actions require an adapter.

CLI Commands

lixity analyze manuscript.md              # Corpus metrics (Rich table report)
lixity analyze manuscript.md --json       # Machine-readable JSON (schema v2 meta)
lixity profile manuscript.md              # Tense & style profiles per paragraph
lixity style manuscript.md                # Self-calibrating style reference
lixity style manuscript.md --json         # Schema v4 JSON (bands, z*, FDR, structural)
lixity style manuscript.md --min-chapters 4 --fdr-method by --json
lixity dialogue manuscript.md             # Dialogue turn structure
lixity characters manuscript.md --names "Anna,Ralf"
lixity pacing manuscript.md               # Scenes, pacing curve, chapter hooks
lixity motifs manuscript.md --motif 'Wut=\b(Wut|wütend\w*)'
lixity showing manuscript.md              # Showing vs. telling balance
lixity dashboard manuscript.md -o ui.html # Standalone interactive HTML dashboard
lixity build [manuscript.md]              # Idempotent workspace (exports/ + archive)
lixity about                              # Engine metadata & heuristic thresholds
lixity completion bash                    # Shell completion script for Bash / Zsh

Python API for AI Agents

from lixity import api

# Analyze corpus KPIs
metrics = api.analyze(text, language="auto")

# Derive self-calibrated style reference (bands, z*, FDR, structural; schema v4)
reference = api.fingerprint(text, language="en")

# Add persistent, editor-visible work markers
new_text, marker = api.add_marker(text, "pruefen", "Verify tense shift", line=42)

# Generate single-file interactive HTML dashboard
html = api.dashboard(text, language="en", title="My Novel")

Frequently Asked Questions

How does self-calibration work?

Instead of comparing your novel against generic newspaper corpora or external averages, Lixity uses robust statistics (median and MAD) across your chapters to derive your manuscript’s own reference house style. Deviations are highlighted only when a chapter departs significantly from your own established voice.

What are structural diagnostics?

Alongside the per-chapter z* heatmap, the style reference reports structural signals over chapter order: PELT changepoints (where the house style shifts), Mann–Kendall trends (monotonic drift), Sn/Qn robust scales next to MAD, Hill tail index for heavy-tailed features, early/late Wasserstein–KS distribution shift, Goh–Barabási fitness on the content-word co-occurrence graph, and Dunning keyness for early vs late chapter halves. They are diagnostic, not verdicts – read them in conjunction with the FDR set.

What are significance-adjusted z* scores?

In short chapters (e.g. 200 words), small sample sizes create large statistical variance. Lixity computes the standard error for every metric (Poisson, binomial, Miller-Madow) and shrinks noisy observations: z* = (x − median) / √(σ² + SE²). This prevents short scenes from triggering false alarms.

How do work markers interact with Markdown editors and book exports?

Work markers are saved as standard HTML comments (<!-- LIXITY-MARKER id="..." kind="..." note="..." -->) directly above the target paragraph. They are visible in plain-text editors (VS Code, Obsidian, Neovim, Ulysses) but completely ignored by document compilers (Pandoc, Typst, LaTeX) when generating PDF, EPUB, or print output.

What languages are supported?

Profiles cover English (en), German (de), French (fr), Spanish (es), Italian (it), Portuguese (pt), and Dutch (nl), plus a generic fallback. English is the default. Select a language or use --language auto for function-word-based detection. Dashboard resources cover all seven languages; CLI messages currently have English and German packs. Heuristic accuracy varies with language and text.

Is Lixity suitable for non-fiction, essays, and scholarly manuscripts?

Yes. Sentence rhythm architecture, lexical richness, readability indices, and self-calibrating consistency analysis apply equally well to essays, dissertations, memoirs, long-form journalism, and technical documentation.

Can Lixity run in automated CI/CD and publishing pipelines?

Yes. Lixity operates entirely offline, executes no network calls, runs on pure Python, produces bit-identical JSON and HTML outputs for identical inputs, and follows standard POSIX exit codes (0 = success, 1 = processing error, 2 = CLI usage error).
