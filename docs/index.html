Architecture & Foundations

The 5 Core Pillars of Lixity

Lixity combines manuscript analysis and dashboard views. An explicit-project research workspace is integrated in v1.19.0.

Pillar 01
📊

Stylistics & Corpus Diagnostics

Descriptive measures of sentence architecture include Average Sentence Length (ASL), rhythm Coefficient of Variation (CV), four length tiers, language-specific readability formula variants, and lexical diversity indices (HD-D, MTLD, Yule's K, Maas a²). Minimum token counts reduce unstable short-text results; the indices are not length-invariant.

ASL / CV HD-D / MTLD Yule's K Flesch-Amstad
Pillar 02
⏱️

Dramaturgy & Tense Profiling

Paragraph-accurate tense continuity without heuristic guessing: detects unintended slips between retrospective epic past and immediate scenic present. Rates tense mixtures across a 4-tier friction severity scale (0–3). Evaluates dialogue ratios, turn lengths, pacing curves, and chapter tension hooks.

Present / Past Friction 0–3 Dialogue Turns Pacing Hooks
Pillar 03
🎯

Robust 3D Style Space

No external dogma: the manuscript is its own baseline. House style is derived robustly via median ± 2 MAD. Chapter deviations are noise-adjusted via analytical z* shrinkage and controlled via Benjamini–Hochberg / BY FDR. Unsupervised latent style axes and interactive 3D narrative trajectories via cyclic Jacobi EVD.

Median ± 2 MAD z* Shrinkage BH/BY FDR 3D Jacobi-EVD
Pillar 04
📖

Shared Project Integration

Reuse the analysis pipeline, versioned JSON and interactive dashboard in an explicit project. Work markers keep review notes near their passages. Typesetting, PDF/EPUB publication, recipient delivery and encrypted NDA storage belong to separate project adapters; they are not bundled core services.

Python API Explicit Configuration Reusable Dashboard Adapter Boundary

🔍

Research & Source Archive

The explicit-project source archive stores UTF-8 and PDF byte hashes, user-supplied context, searchable passages, citations, manual claims and authorial decisions with immutable revision history and offline diagram rendering. It supports controlled withdrawal and purge; it does not verify historical truth.

Practical Macro-Editing

Macro-Editing Matrix & Editorial Heuristics

Statistical metrics are not an objective quality score or an instruction to rewrite prose. They point to passages a human reader may want to inspect. FDR results depend on model assumptions and do not guarantee a fixed false-positive rate for every manuscript.

Linguistic Feature Calculation & Signal Editorial Role & Application Warning Signal & Intervention
Sentence Rhythm & Length Tiers ASL, rhythm CV, staccato (≤6w), hypotaxis (>25w) Pacing: Sentence-length variation can draw attention to shifts between action, dialogue and reflection. Low or high CV and changes in long-sentence frequency invite a read of the passage; neither implies good or bad prose.
Lexical Diversity Hypergeometric HD-D (McCarthy & Jarvis), MTLD, Yule's K Vocabulary Pattern: These measures reduce some length sensitivity compared with raw TTR, subject to token floors and corpus context. A later change may prompt a look at repetition, dialogue mix or topic shifts; it does not identify author fatigue or a quality problem.
Tense Continuity & Friction Present, past, friction rating 0–3 Timeline & Perspective: Heuristic labels help locate tense changes at paragraph scale. Higher friction may merit a check of quotation, dialogue, flashback or deliberate perspective shifts before treating it as an error.
Showing vs. Telling & Filters Perception verbs, passive voice, nominal style Register: Word-pattern counts highlight possible changes in viewpoint or exposition. Read passages in context; these constructions can be deliberate and their counts do not measure immersion.
FDR Heatmap Noise-aware z* shrinkage, Benjamini-Hochberg (●), Cliff's δ Statistical Review: A dot marks a cell passing the configured FDR procedure under its assumptions. Effect size adds context. Read flagged passages in context; a flag neither proves a defect nor calls for a rewrite. Unflagged passages can still matter artistically.
Structural & Drift Diagnostics PELT changepoints (BIC), Mann-Kendall τ, Wasserstein-KS Narrative Structure: These measures locate changes and trends in the selected features. A change point can prompt review of scene, character or chapter context; it does not identify an author handover or its cause.
Persistent Work Markers <!-- LIXITY-MARKER id="..." kind="pruefen" --> Traceable Editorial Annotations: Notes remain anchored near the target paragraph in Markdown. Export treatment is controlled by the project adapter. Content hashes identify the originally marked paragraph; review anchors after manuscript edits.

Local Research & Traceable Passage Citations

The experimental research pilot keeps archived source bytes, user-supplied context, manuscript text, and authorial records separate. It helps writers trace a passage behind a claim and record why they made a narrative decision. Sources and claim labels remain material for human review, not certified facts.

1. Immutable Text Archive

Local UTF-8 source bytes are retained with SHA-256 digests after explicit --allow-retention confirmation. Retention does not grant redistribution rights.

2. Versioned Source Criticism

Stores user-supplied creation period, depicted period, place, genre, perspective, translation status, provenance note, and tags without changing the source bytes.

3. Verifiable Passage Citations

Archived passages have UUIDs and Unicode character offsets. Authors may create claims separately, then link a passage as supporting, contradicting, qualifying, or contextual evidence. A link does not prove a claim.

4. Governed Lifecycle

Withdrawal excludes a source from current search while preserving citation history. Purge removes retained records and unshared source bytes; a dry run previews the effect. Authorial decisions can mark an intentional departure from evidence.

Terminal Research Workflow (CLI)

# 1. Initialize a dedicated research workspace
lixity research init --project ./novel-research --title "1920s Archive" --language en

# 2. Ingest primary source with cultural source criticism and explicit retention
lixity research ingest --project ./novel-research --file ./sources/police_log_1923.txt \
  --context '{"genre": "Police Log", "created_period": "1923", "place": "Hamburg", "provenance_note": "State Archives"}' \
  --allow-retention

# 3. Build SQLite FTS5 lexical index
lixity research reindex --project ./novel-research

# 4. Fast lexical full-text search with BM25 ranking
lixity research search --project ./novel-research --query "dockyard customs" --limit 5

# 5. Resolve a passage citation (paragraph, exact offset, source metadata)
lixity research cite --project ./novel-research --passage urn:uuid:PASSAGE-UUID-HERE

# 6. Run linguistic source analysis and generate standalone source dashboard
lixity research analyze --project ./novel-research --source-id urn:uuid:SOURCE-UUID-HERE
lixity research dashboard --project ./novel-research --source-id urn:uuid:SOURCE-UUID-HERE > source_report.html

# 7. Compare source and manuscript vocabulary; create a dossier
lixity research compare --project ./novel-research --source-id urn:uuid:SOURCE-UUID-HERE --manuscript ./manuscript.md
lixity research dossier --project ./novel-research --title "Harbor Evidence" --file "Summary..." --tags "harbor"

# 8. Record a claim, passage relation, and authorial decision
lixity research claim --project ./novel-research --title "Harbor opening" --statement "The harbor opened in 1923." --confidence hypothetical
lixity research link-evidence --project ./novel-research --claim-id urn:uuid:CLAIM-UUID-HERE --passage-id urn:uuid:PASSAGE-UUID-HERE --relation supports
lixity research decision --project ./novel-research --title "Shift opening date" --rationale "Narrative chronology" --claim-id urn:uuid:CLAIM-UUID-HERE --deviation-from-fact

# 9. Open the interactive research dashboard
lixity serve --research-project ./novel-research --no-project

# 10. Audit repository integrity and snapshot checksums
lixity research audit --project ./novel-research

In the server UI, Open Project offers Browse files and folders for paths on the computer running Lixity. Browse from the server user's home, use Home or Parent folder, select a manuscript or the current folder, then confirm with Open; a typed path also works. Opening reconnects the original workspace and its research archive, including a research-only folder without a manuscript. Manuscript comparison needs a manuscript; browser file import creates a separate project from its bytes. Welcome guidance can be hidden and reopened without hiding the project controls. Source and dossier details, direct search-to-evidence actions, and dossier-linked claims are available in the v1.19.0 research workspace. Included in v1.19.0: optional Zotero Desktop integration adds collection browsing, selected PDF/text capture, explicit refresh and original-item links. Media management stays in Zotero; Lixity preserves evidence and authored decisions. Additive migration export and paired backup tools are available; migration is explicit and does not remove archive history. See the implemented research commands and the broader research RFC.

Source/manuscript comparison uses chapter prose without headings, front matter or the configured appendix. Cross-language lexical scores remain numeric but carry an explicit comparability warning; they are not a factual or linguistic-equivalence verdict.

Developers & Autonomous Agents

CLI Commands & Python API for AI Agents

Lixity offers deterministic, versioned JSON contracts (analyze/profile v2, style v4) and stable POSIX exit codes for autonomous coding and editing agents.

Command-Line Interface (CLI)

# Analyze manuscript (rich terminal report or JSON)
lixity analyze manuscript.md              # Visual terminal report
lixity analyze manuscript.md --json       # Machine-readable JSON (schema v2)

# Tense profiling & narrative dynamics
lixity profile manuscript.md              # Paragraph-accurate tense & style profile
lixity dialogue manuscript.md             # Speech ratios & dialogue turns
lixity characters manuscript.md --names "Anna,Ralf" # Character presence
lixity pacing manuscript.md               # Scene tempo & chapter hooks
lixity showing manuscript.md              # Showing vs. telling balance

# Self-calibrating style reference & structural diagnostics
lixity style manuscript.md                # Median/MAD bounds, z*, FDR matrix
lixity style manuscript.md --json --fdr-method by --min-chapters 4

# Interactive dashboard & idempotent workspace build
lixity dashboard manuscript.md -o exports/dashboard.html # Standalone single-file HTML
lixity build manuscript.md --language en  # Idempotent workspace build with archive rotation
lixity serve --port 8765                 # Local development server & interactive workspace

# Evidence-based research workspace (pilot)
lixity research init --project ./research --title "Archival Study"
lixity research ingest --project ./research --file log.txt --allow-retention
lixity research search --project ./research --query "warehouse gate"
lixity research dossier --project ./research --title "Smuggling Dossier" --file "Summary..."
lixity research compare --project ./research --source-id <source_id> --manuscript manuscript.md

Python API for AI Agents

from lixity import api
from lixity.research import api as research_api

# 1. Compute corpus KPIs & readability
metrics = api.analyze(text, language="auto")

# 2. Self-calibrating style reference with FDR & structural diagnostics (schema v4)
reference = api.fingerprint(text, language="en")

# 3. Add persistent editorial work markers
updated_text, marker = api.add_marker(text, kind="pruefen", note="Verify tense shift", line=42)

# 4. Generate standalone interactive dashboard
dashboard_html = api.dashboard(text, language="en", title="My Novel")

# 5. Research workspace: archival ingestion, FTS5 search & dossiers
research_api.init(proj_path, title="1920s Investigation", language="en")
ingest_res = research_api.ingest(proj_path, "customs_1923.txt", allow_retention=True)
search_res = research_api.search(proj_path, "warehouse customs", limit=5)
dos_res = research_api.create_dossier(proj_path, title="Evidence Brief", body="...", evidence_ids=[...])

Setup & Get Started

Installation & Quickstart

Install Lixity in an isolated CLI environment on Linux, macOS, or Windows using uv (or pipx). No account, no API key, and no cloud manuscript uploads required. 

# Install via uv (recommended; requires Git & uv)
uv tool install --python 3.12 "git+https://github.com/mfahsold/lixity.git@v1.19.0"

# Verify installation
lixity --version
lixity about

# Build your first manuscript dashboard
lixity build manuscript.md --language en

Open exports/manuscript_dashboard.html in any modern browser. Full setup guide for Windows/macOS, shell completions, and troubleshooting: docs/INSTALLATION.md.
