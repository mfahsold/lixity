Lixity

Quantitative text linguistics, length-invariant stylometry, and a self-calibrating style passport for literary manuscripts. Pure Python, offline, deterministic, seven languages.

Target Personas & Workflows

Fiction Authors & Novelists

Macro-editing and pacing diagnostics: detect accidental slips between narrative present and past, balance dialogue with prose, and evaluate rhythm variation (CV) across chapters.

Literary Editors & Translators

Objective chapter consistency inspection without arbitrary external dogmas. Insert persistent, editor-visible work markers (<!-- LIXITY-MARKER ... -->) that vanish in final print and EPUB exports.

Digital Humanities Scholars

Rigorous, reproducible corpus stylometry: length-invariant lexical diversity (HD-D, Yule’s K), Miller-Madow bias-corrected Shannon entropy, and Jacobi eigendecomposition in pure Python.

AI Agent & Pipeline Engineers

Deterministic JSON contracts (schema_version: 2), standardized exit codes, and a stable programmatic facade (lixity.api) designed for autonomous coding and editing agents.

What Lixity Measures

Sentence Rhythm

Average sentence length (ASL), coefficient of variation (CV), and length distribution from staccato (≤ 6 words) to hypotaxis (> 25 words).

Lexical Diversity

Length-robust measures: Guiraud R, hypergeometric HD-D (McCarthy & Jarvis 2010), and Yule’s characteristic K for vocabulary concentration.

Tense Dynamics

Paragraph-by-paragraph detection of narrative present vs. epic past, line anchors, and friction severity flags (0–3).

Register Signals

Dialogue share, function-word ratio, sensory perception filters, modal density, passive markers, and nominal style suffixes.

Self-Calibrating Passport

The manuscript’s own house style derived via median/MAD, significance-adjusted deviations z*, and Benjamini-Hochberg FDR control.

Style Dimensions

Unsupervised discovery of latent stylistic axes via Spearman rank correlation and cyclic Jacobi eigendecomposition.

CLI Commands

lixity analyze manuscript.md              # Corpus metrics (Rich table report)
lixity analyze manuscript.md --json       # Machine-readable JSON (schema v1)
lixity profile manuscript.md              # Tense & style profiles per paragraph
lixity style manuscript.md                # Self-calibrating style passport
lixity style manuscript.md --json         # Schema v2 JSON (bands, z*, FDR, dimensions)
lixity dashboard manuscript.md -o ui.html # Standalone interactive HTML dashboard
lixity about                              # Engine metadata & heuristic thresholds
lixity completion bash                    # Shell completion script for Bash / Zsh

Python API for AI Agents

from lixity import api

# Analyze corpus KPIs
metrics = api.analyze(text, language="auto")

# Derive self-calibrated style passport (bands, z*, FDR, dimensions)
passport = api.fingerprint(text, language="de")

# Add persistent, editor-visible work markers
new_text, marker = api.add_marker(text, "pruefen", "Verify tense shift", line=42)

# Generate single-file interactive HTML dashboard
html = api.dashboard(text, language="de", title="My Novel")

Frequently Asked Questions

How does self-calibration work?

Instead of comparing your novel against generic newspaper corpora or external averages, Lixity uses robust statistics (median and MAD) across your chapters to derive your manuscript’s own reference house style. Deviations are highlighted only when a chapter deviates significantly from your own norm.

What are significance-adjusted z* scores?

In short chapters (e.g. 200 words), small sample sizes create large statistical variance. Lixity computes the standard error for every metric (Poisson, binomial, Miller-Madow) and shrinks noisy observations: z* = (x - median) / √(σ² + SE²). This prevents short scenes from triggering false alarms.

How do work markers interact with Markdown editors?

Work markers are saved as standard HTML comments (<!-- LIXITY-MARKER id="..." kind="..." note="..." -->) directly above the target paragraph. They are visible in text editors (VS Code, Obsidian, Neovim) but completely ignored by book exporters (Pandoc, Typst, LaTeX).

What languages are supported?

Native profiles exist for German (de), English (en), French (fr), Spanish (es), Italian (it), Portuguese (pt), and Dutch (nl), plus a generic fallback. Languages can be specified explicitly or auto-detected.
